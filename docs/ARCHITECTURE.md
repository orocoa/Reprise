# Reprise 架构：保存一稿、看过去、取出副本

## 入口与运行包

主要调用链是 `agent → 薄 Skill → 随包 reprise 入口 → 同一 CLI/service → 本地工作台`。Skill 根据对话语言显式传 `--lang zh|en`；文件夹首次保存按用户选择持久化截图偏好，后续 `save`/`snapshot` 沿用。只打开工具使用 `open --workbench`，查看已有 Git 路线使用 `open PATH`。浏览器和 CLI 共用 `experience.save_draft`，文件保存与画面结果分开返回。没有第二套 agent 存储逻辑，也不要求在工作台配置模型。

主交付是源码 Skill、脚本和工作台源码；Python/Git、截图所需的 Node/Playwright/浏览器由 Agent 先复用宿主，再按已有授权补齐。完整 macOS 运行工具测试包已经撤回。`desktop_bundle.py`、`desktop_entry.py`、`scripts/build_macos_bundle.py` 与原生窗口原型继续作为历史兼容源码保留，不作为当前安装入口或新机器安装通过的证据。

历史 `connect-skill --to` 入口仍保留其路径和权限边界。当前源码 Skill 使用其绝对脚本入口与同一核心，不更改用户模型或全局权限设置。包身份由清单和来源散列核验，不能仅按版本号或文件名判断。

## 版本操作与弹窗生命周期

版本详情通过 `version_actions.py` 统一返回精确项目/SHA 的动作契约。预览控制器管理请求与等待画面的归属，弹窗控制器管理打开、替换、返回、关闭；恢复位置策略分离候选来源和安全校验。选择页与删除计划复用相同作用定义。[完整说明 / English](VERSION-ACTIONS.md)。

## 当前产品主线

Reprise 的主要使用者不需要理解 Git、SHA、配方或内容库。普通文件夹的主要任务是主动保存一稿，凭时间、名称和这一稿的真实画面找到过去，再把所需文件取出到新的副本目录。整理重复资料、删除历史、迁移和环境维护保留为高级任务，不成为完成这三步的前提。

| 使用者任务 | 负责模块 | 必须保留的边界 |
| --- | --- | --- |
| 保存一稿 | `service.py`、`projects.py`、`folders.py` | 保存源目录的确切内容，未完成不称已保存；不自动删除原件 |
| 凭画面看过去 | `experience.py`、`workspace.py`、`evidence.py` | 只显示该项目、该完整版本的资料，缺失不能借用邻版画面 |
| 为网页补画面 | `quick_preview.py`、`experience.py`、既有 capture/runtime | 只读准备静态入口，明确保存后才运行、采集 |
| 取出副本 | `recovery_destination.py`、`recovery.py`、repository 的 `materialize` | 默认提供新位置，执行时复核，不覆盖源目录或已有目标 |

把技术详情收到按需展开项，不意味着取消底层校验。界面应先回答“保存了哪一稿”“是否有这一稿的画面”“副本取到了哪里”；完整版本标识、回执、配方和错误日志仍可查。文件恢复成功不等于网页运行成功，保存成功也不等于截图成功。

已有 Git 项目仍是独立的只读来源：Reprise 不替用户提交、checkout、reset 或 fetch。Git 项目能被读取与历史网页能否运行是两个能力。项目名称、路径、固定 SHA、路由和用户模型设置不得进入通用核心源码。

## 主流程的交互收口

浏览器快捷留稿继续调用原有 snapshot API；只有已明确保存项目截图偏好后才直接保存，首次范围说明仍保留。自动名称不制造新内容版本；内容未变化时沿用已有稿件。重复点击共用当前保存请求，后台完成不抢走用户正在浏览的版本。

截图偏好仍由现有 preview-preferences 接口持久化，复用明确批准的精确版本配置。 首次选择是可以保存为 auto + pending_recipe，先持久化意图而不批准任何检测命令；第一份显式保存的可采集配置完成该待配置选择。只有保存配置的写入路径能绑定模板，检测只返回计划。失败不重置答案，较新的否选择不被排队任务重新开启。整稿恢复后的继续指令只引用已完成回执中的新路径和完整 SHA；导出、部分文件或失败结果不显示完整网页继续指令。复制文本不发送消息，也不自动改变另一聊天的工作目录。

当前 Agent 可按用户对本轮前后留稿的明确委托编排两次现有调用；没有新后台监听器。功能入口与冻结边界见 [FEATURES.md](FEATURES.md)。

## 请求编排与模块边界

`server.py` 负责本机 HTTP 的 Host、Origin、token、请求形状与路由，将任务交给应用层；不在路由里复制截图筛选、配方推断、目录生成或恢复逻辑。CLI 和 Skill 继续使用同一个核心。`experience.py` 是面向上述任务的少量函数编排，不是新存储层，也不新增服务进程、任务队列或插件系统。

```text
web/ ─ server.py ─ experience.py ─┐
run.py / cli.py ─────────────────┼─ service.py ─ projects.py
                                │                 ├─ folders.py ─ 自有内容库
                                │                 └─ git.py / archives.py ─ 只读来源
                                ├─ workspace.py / evidence.py ─ 历史与准确画面
                                ├─ recovery_destination.py / recovery.py ─ 新副本与回执
                                ├─ jobs.py ─ runtime.py ─ processes.py ─ 运行副本
                                │           └─ capture.py / browser_worker.mjs ─ 采集
                                └─ 高级维护 / 可选 AI ─ 沿用既有模块和确认边界
```

### 画面历史

`visual_history` 以当前工作空间提供的项目来源与完整 SHA 为依据，批量返回每一版可以使用的登记画面。记录级和媒体项级的版本归属都必须匹配；缺失文件、无效媒体和另一版本的画面不能作为缩略图回填。优先使用完成且无错误的资料，再按采集时间选择；保留状态、警告与错误，不把诊断截图当作成功验证。人工资料仍标明归属由提供者指定，旧资料不升级为重新采集验证。历史读取不启动网页、不截图、不改变当前选择；失败或无画面应返回明确状态。

### 快速准备网页画面

`quick_preview.py` 只读确切版本，准备无需安装或构建的静态网页入口；不继承项目命令。入口不唯一时要求选择，缺少本地资源或检测到直接引用网络资源时转到配置说明。静态候选固定本机网络、无命令和有限采集场景；准备成功只是没有已知静态阻碍，不保证实际运行成功。

`experience.plan_draft_preview` 在准备结果上保护该完整 SHA 已保存的配置：不同配置不自动覆盖，引导使用原有设置。执行需要明确的“保存配置并截图”或在已说明静态截图范围的对话框保存一稿；经现有 `save_recipe` 验证并绑定精确版本后，进入已有任务队列与 capture 流程。相同配置不反复追加保存历史。未明确请求截图的普通保存不启动浏览器。

这条路径减少普通用户填写 JSON 的负担，不新增命令批准捷径。未识别项目保留手动配置/人工资料入口；缺依赖、缺入口或历史环境不能运行时，文件版本仍然可查和取回。自动截图偏好继续遵循用户已明确保存的模板授权，不从另一版默默继承命令批准。

### 新副本位置

`suggest_destination(recoveries, project_id, full_sha)` 验证项目与精确版本，推荐原项目同级、尚不存在的新目录，使取出的副本可以继续编辑并作为新文件夹项目加入。父目录须存在、可写且路径不经过符号链接；目标须与 Reprise 数据目录及已登记源保持安全边界。已保存的普通文件夹即使原件缺失，只要父目录可用仍可推荐同级位置；父目录不可用时明确要求用户更改位置，不回退到应用数据内部。支持 SHA-1 与 SHA-256，不接受 HEAD 或缩写，不枚举用户目录，也不提前创建或预留目标。界面自动填入建议位置，可展开改到用户选择的新路径；真正恢复仍复核来源保护、目标占用和排他创建。

`RecoveryStore.create` 在任何回执目录写入前检查目标，借用已有逐级 no-follow I/O，以目录描述符创建回执目录并原子写入回执。管理根在 mkdir 前被换成链接，不能把这次目录写入重定向到源文件夹。此边界不等于对任意恶意同用户进程的文件系统隔离。

## 内容与版本身份

Git 或 Reprise 自有快照库是版本内容的来源；项目注册表记录本机路径和人工配置；运行目录是某一 SHA 的独立副本；画面资料是带来源的独立记录。它们不能相互冒充，列表相邻项也不代表父子关系。

普通文件夹通过 `folders.py` 使用 `kind: folder` 的项目记录。快照写入 Reprise 自有的 `content/objects.git` 裸仓库，按项目 ref 分隔历史，跨文件夹共用内容对象；源文件夹及已有 Git 仓库不执行写操作。`payload/` 保存原始文件字节，`snapshot.json` 保存来源、模式、修改时间、空目录、指纹和排除项。适配器仅向现有 tree/blob/diff/materialize 接口暴露原文件，管理清单不会混入用户内容。快照父边是真实保存顺序，不宣称是源项目原有的 Git 提交。

记录版本使用全内容库写锁，读取和恢复使用已发布不可变对象。新增或元数据变化的文件按块读取和校验；相同签名的未变文件复用已有对象，签名包含设备、inode、类型/权限、大小及纳秒 mtime/ctime。读取前后及发布前重新核对目录清单，发现并发变化则不推进项目 ref。文件描述符以不跟随符号链接的方式逐级打开；不执行 filters、hooks 或源码命令。元数据签名用于增量优化，不是对任意宿主篡改的完整性保证；恢复逐对象验证原始内容。所有原件、索引、失败对象与回执保留，没有自动回收。

恢复请求可携带明确的相对文件/目录列表，排队时固定完整 SHA 和范围；Git 和文件夹共用这一能力。内容统计区分逻辑字节、当前快照不同内容字节、本次新增内容字节，不冒充文件系统独占块或磁盘释放量。本轮只有本机内容库，没有远端同步、源文件移除或 Git 暂存/提交/推送接口。

### Git 对象层

`Repository` 使用系统 Git 的 `rev-parse`、`for-each-ref`、`log`、`ls-tree`、`diff-tree`、`cat-file`、`status` 等命令，通过 argv 和 NUL 分隔传递结果。支持普通工作仓库、裸仓库、linked worktree、未提交的空仓库、detached HEAD、SHA-1 / SHA-256 仓库。对路径使用 filesystem surrogateescape，避免空格、Tab、换行破坏解析。

每个提交保留完整 SHA、真实 parents、作者、时间及引用。默认 diff 使用真实第一父节点；合并提交可选择其他父节点；根提交与空树比较。浅克隆缺失父对象时仍显示提交和现有证据，并指出差异不可读。历史实时从 Git 读取，不再依赖预生成的 61 项目录。

还原直接读取 Git blob，验证对象内容，写入新建的托管目录。不 checkout 源工作区，不修改源 index，不运行仓库 hooks / smudge 过滤器，不自动 fetch。子模块保留 gitlink 信息；LFS 指针明确标记。危险路径、越界符号链接、不可表示的文件和超限输出必须失败并说明，不能悄悄替换内容。

工作树状态在独立的只读 Git 元数据视图中计算：复制 index/sharedindex、HEAD 和影响内置转换的安全配置，原对象目录只供读取；最终 status 不加载源配置或 include，因此即使源配置并发新增 clean/process 驱动也不会执行。CRLF、working-tree-encoding 等内置转换保留。未执行的自定义过滤转换可能让文件显示 modified，返回状态明确说明这一限制。视图按内容哈希复用，保留在应用数据的 `git-status/` 私有目录。

### 项目注册与能力识别

`ProjectStore` 只保存稳定项目 ID、规范化路径、显示名称和人工配方。HEAD 和 history 随时重新读 Git。识别缓存以仓库路径 + 精确 SHA 为键。`detection.py` 读取提交内的 manifests 和 HTML，返回识别信号、置信度、候选根目录、警告和能力。

无须能够识别框架，才能浏览仓库。未知类型仍有 history/diff/manual 能力。识别到框架也不代表它当前可运行；只有实际配方和运行结果能说明运行能力。Canvas 是绘图技术，单独出现不能证明项目是游戏。

配方优先级：当前完整 SHA 的人工配置 > 当前提交的 `.reprise.json` > 自动静态识别。提交里的命令型配方是未批准输入，必须在工作台核对保存。历史版本可以有不同入口和配置；执行任务前锁定 SHA 与规范化配方副本，避免排队期间 HEAD 或配置变化改写请求。

## 运行适配与生命周期

运行适配器目前有 `static-web`、`command-web`、`manual`。适配器读取同一配方契约，持有独立副本、进程身份、就绪状态和日志。静态网页使用专用 loopback HTTP 服务，支持视频 Range、WASM MIME 和跨来源隔离头。命令型适配器按 install → build → start 执行 argv，端口由系统分配并传入 `{port}` / `PORT`。

运行进程使用新 session，停止时校验 PID 与启动身份。API 与项目预览使用不同来源，项目脚本得不到管理 API 的跨源读取权限。停止保留文件；没有自动清理、自动提交、自动推送流程。线程池限制任务并发，同项目由持久锁防止 CLI 与服务并行覆盖；服务重启识别已中断任务。

可信 Python 启动入口先等待进程所有权登记，再以 exec 执行目标 argv；短命令也不能抢先退出而丢失身份。各 install/build/start 阶段分别保留进程树记录，安装与构建结束后清理其后代，再进入下一阶段。观察器登记后代和会话；可信启动器在执行命令前注入随机所有权标记，macOS/Linux 从内核读取标记以追踪快速双重 fork、重新归属及独立会话的后代。只保留标记，不持久化其他进程环境。父进程退出不等于整树退出；停止前进行两次独立所有权扫描并再次核验身份，对顽固进程升级到 KILL，并确认结果。身份或清理无法确认时保存 `cleanup_failed`，接口报错，界面保留“停止未确认”与重试入口。尚在准备/启动的任务使用取消任务，不能通过停止接口制造先停止后启动的竞态。

静态服务器由可信绝对脚本通过 `python -I -S` 启动，不搜索仓库或继承的 Python 路径，并精确校验 loopback Host。进程跟踪用于生命周期管理，不能保证归因一个主动清除所有权标记且从未被观察到的恶意后台进程；这仍属于下面的容器/虚拟机隔离范围。

这些进程以当前本机用户权限运行。若要运行不可信仓库，需要后续容器/虚拟机 adapter；不能把“独立副本”叫作沙箱。现阶段明确的命令配置与执行动作承担授权边界。

## 确定性采集与证据

采集输入是 `project_id + target SHA + base SHA + target recipe hash + effective base recipe hash + runner version`。两个版本分别使用各自的适配器、根目录、启动命令与就绪条件；路由、视口、操作、录屏和网络策略使用目标版本定义的同一组采集场景。基准配置缺失或未批准时拒绝执行并指出需配置的 SHA；缺资源保留诊断，不从其他版本回填。

浏览器从独立上下文启动，等待页面、fonts、图片 decode、媒体 metadata 与指定的 app-ready 选择器。全页采集先触发可见范围内的懒加载，再恢复位置；交互按有限步骤执行。PNG 保留像素尺寸；录像记录自己的宽高。HTTP 失败、脚本错误、缺图和阻断请求会降低记录状态，诊断截图不标成通过。

`network:local` 只允许当前运行实例来源，以及 data/blob；`allow` 是显式放宽的浏览器网络策略。捕获器不用 AI。成功缓存必须匹配全部采集输入且产物仍存在；失败和部分成功不会阻止重试。每次运行/失败的日志和产物独立保留。

人工证据复制到托管存储，明确标记 `source:manual / verification:user-supplied`，绑定用户指定的 SHA，并保留原路径和内容哈希。历史导入证据标为 legacy，保留原始采集元数据，不冒充新引擎重跑验证。只有具有相同场景/媒体类型/两侧 SHA 的资料才能被直观成对呈现。

## 可选 AI 边界

模型适配器只接受有限的已提交清单、路径和差异元数据，只返回结构化提案。输出通过 `validate_recipe` 与文件依据检查，包含 provider/model、输入哈希和提示词版本。提案要求一次包含 zh/en 两种语言的标题、摘要和变化说明，缺失或超出限制即拒绝；提示词版本进入缓存键，旧版单语缓存不会被复用。提案不会自动保存、执行或变成验证证据。审阅后的版本说明由独立 notes 接口绑定完整 SHA；说明保存不批准配方，原始 Git 消息保留。连接配置在请求途中变化时，旧响应丢弃。当前实现兼容 Chat Completions 接口，可通过替换 provider adapter 接入其他供应商；旧原型里的 Codex 配置不被迁移或改写。

## 数据目录

```text
<application data>/
  projects.json                 项目注册 + version_recipes / version_notes（完整 SHA）+ 保存历史
  content/objects.git/          普通文件夹的自有内容对象、清单和版本引用
  content/*transaction*.json    保存/删除事务，失败和完成记录保留
  jobs/<id>.json                任务和恢复状态
  recoveries/<id>/receipt.json  恢复/导出范围、准确版本、结果与目标位置
  recoveries/<id>/snapshot/     原有默认托管恢复副本
  # 普通用户的新副本位于原项目同级的 Restored-*，在应用数据目录之外
  runtimes/<id>/runtime.json    进程身份与配置哈希
  runtimes/<id>/process-*.json  各阶段的进程树所有权及清理记录
  runtimes/<id>/source/         精确提交的独立副本
  runtimes/<id>/runtime.log     安装 / 构建 / 启动日志
  evidence/<id>/record.json     SHA、配方、来源、诊断、媒体元数据

  ai/proposals/                 已校验但未自动执行的模型提案
  git-status/<hash>/             可复用的私有 Git 状态元数据视图
```

应用数据应放在源仓库以外。读取 Git、刷新列表、切换项目不创建预览副本。只有运行、采集、人工导入等具体操作才写相应托管内容。

## 版本配置与取消任务

人工配置只对保存时解析出的完整 SHA 生效。`HEAD` 前进后不继承上一提交的批准。已有 `recipe` 字段原样保留并通过 `legacy_recipe` 暴露为草稿，不再跨版本自动生效；用户可在指定版本载入并保存。清除某版本覆盖配置使用 `recipe:null`，保留保存历史后回退到提交配置/识别。

运行与采集使用持久取消请求和协作式检查，状态为 queued → running → cancelling → cancelled（清理失败则 failed）。排队取消释放项目锁；运行中取消覆盖快照、安装/构建、服务就绪、采集锁等待及浏览器阶段。只停止具有匹配进程身份的自有进程；部分输出与日志保留。任务完成后取消为幂等操作，不停止已经交付的预览；此时使用运行实例的停止接口。CLI 与服务共享取消请求。

每份任务记录独立校验；损坏 JSON、结构、编码或读取错误通过 `job_warnings` 显示，跳过该条但保留原文件，不阻止其他任务和工作台启动。

运行实例从准备到就绪持有独立 `startup.lock`，启动子进程不会继承该锁。服务异常退出时操作系统释放锁；恢复时先取得锁并重读记录，避免把刚完成的启动误判为中断。仍处于启动阶段的实例显示 `interrupted`，可通过原进程所有权记录停止残留进程。存活启动任务继续使用取消入口。旧记录以来源、完整 SHA 和任务执行时间关联启动所有者；无法核验时明确报告，不根据 PID 或空身份猜测进程已退出。恢复不会执行配方，也不删除副本、日志或媒体。

采集任务无论完成、部分失败或取消，都使对应项目与精确 SHA 的详情缓存失效；可见结果更新，不切换用户当前版本。预览与设置提供可展开的具体错误、警告及本机日志位置；这些路径仅作为文字展示，HTTP 仍只提供登记的媒体。`live-evidence.js` 统一资料的 SHA、侧别、类型和可用性，预览、对比和查看器共用；普通文件保留链接，图片/视频轮播排除缺失或无效项。

### 命令入口与网页

`reprise .` / `open` 从当前目录定位仓库，检查数据目录不位于源仓库内，再启动或复用服务。启动通过可信绝对 `server_entry.py`、`python -I -S` 和托管工作目录，不搜索项目模块。复用检查 PID 启动身份、健康接口实例随机标记与数据目录；不按端口猜测服务。`--no-browser` 返回 JSON，`shutdown` 通过带 token 的本机接口取消任务并停止预览，无法确认清理就报错。

`web/` 是通用核心唯一前端编辑源，实际脚本与样式入口以 `index.html` 为准。`live.js` 保持共享状态与事件分派；历史、资料、文件内容、恢复、导入和高级维护在对应 `live-*.js` 中实现。产品主线只组合这些既有能力，不用第二套历史或恢复状态覆盖核心数据。操作通过命名 handler 表由一个入口分派；刷新按控件的任务、运行、资料或文件标识恢复焦点，异步结果不抢回其他区域的焦点。手工导入子页保留原设置节点、展开状态和滚动位置，返回及 Escape 恢复原入口。旧 app/shell/Paper Grid 文件与视觉档案保留，但不在当前页面执行。不在核心内保留具体项目路径、固定版本或用户模型设置。

## Git 历史、比较与关联存档

Git 关系图的节点、父边、参考线、轨道复用、避碰、像素投影及换仓库回归要求，统一见 [Git 图实现契约](GIT-GRAPH.md)。视觉调整不能改写真实父关系，筛选不能删掉关系节点。

`workspace.py` 提供通用历史快照、显式关联存档、比较来源选择与双侧文件文本。`web/live*.js` 和 `graph-layout.js` 是当前正式界面，读取 `/api/workspace/*` 和原有版本、运行、资料 API。启动 URL 中的项目标识决定上下文；agent 从当前项目或显式路径直接打开，不增加界面选仓库流程。刷新后旧详情响应不再写入新缓存。旧 `app.js` 和 Paper Grid 视觉档案继续保留。

关联存档先验证共同 Git 提交，再保存本机注册信息；按完整 SHA 去重，保留每条版本的读取来源。目录筛选只影响存档显示，不删除 Git 对象。路线只依据真实 parents，独立记录显示分隔说明。媒体以完整 SHA 和采集场景匹配；手工资料没有场景元数据时不会自动伪造成前后对照。AI 提案和运行配置仍须单独明确保存。

## 资源预算与维护

不增加前端框架、数据库、常驻 Node 服务或 Python 第三方依赖。管理服务只有 Python HTTP 服务和按需启动的任务/预览；Node 与浏览器仅在采集时使用。空闲取消观察器阻塞等待，存在可取消任务时才每 100ms 检查跨进程取消请求。

历史最多读取 64 个不同 tip，每个 tip 最多 2000 条，超限保留父 SHA 边界并返回警告。每个 tip 一次 Git 遍历；已加载且祖先完整、数量未超限的历史直接复用。不能改成所有分支共享一个全局数量限制，从而丢掉冷门支线。快照指纹包含说明、引用及存档显示集合的变化；不提供整个仓库原子事务的保证。

前端按完整 SHA 建立提交索引。详情缓存最多 128 项，当前选中、比较两侧与预览基准保留；逐版本文件路径独立保存，淘汰详情不会破坏文件搜索。重复搜索复用已读取路径，刷新清空以恢复缺失对象。翻译表只编译一次，文本缓存最多 512 项；局部 DOM 更新只翻译变化区域。图片变化区域缓存最多 64 项。任务状态不变时不重建详情页面。

证据 HTTP 路径只提供该记录登记的 items；采集输入、所有权记录与日志仍保留在本地，不随媒体地址公开。视频和大文件按块传输，支持 Range；不把整份媒体读入内存。

当前图仍渲染整个已加载集合，文件搜索首次仍需读取各版本差异，保留的磁盘证据没有自动清理。这些是明确的规模边界。只有实际长历史测量证明需要时，再加入虚拟列表或索引数据库；保持完整 SHA、全部有序父边和历史来源契约。

`tests/workspace-cache.test.cjs` 验证缓存淘汰后搜索与比较仍正确；Python 与真实浏览器回归验证业务/安全边界。CI 配置覆盖 macOS/Linux、最低 Python 与另一版本，以及全新安装；配置存在不等于远端执行已通过。

## 共用入口、便携 Skill 与恢复

`skills/reprise/` 仅维护通用指令和 CLI 入口，`scripts/build_skill.py` 在构建时收集 canonical Python 核心、web 资源与许可，生成自包含 ZIP 及逐文件 SHA-256 manifest。入口从自己的文件位置定位运行时，无全局 agent 环境或当前目录假设。WorkBuddy 变体仅增加其平台所需的前置元数据。客户端加载、运行包 CLI 与真实浏览器分别验证，不把标准兼容等同于每个 agent 的实际调用成功。

`recovery.py` 复用 `Repository.materialize`，与运行进程、证据及 Git 身份分离。排队前固定 SHA，恢复路径不得存在，也不得位于任何登记的源 worktree、Git 目录或共用 Git 目录内；执行时复查并独占创建。ZIP 保留安全符号链接和执行位，托管 ZIP 通过已完成回执提供下载，外部 CLI 导出路径不通过 HTTP 公开。恢复是文件快照，不伪造 Git 历史。回执、部分结果和快照无自动删除。

`live-workspace.js` 管理恢复对话框、结果和按需嵌入预览；新任务沿用持久任务队列与取消机制。agent 负责确定项目，CLI 默认使用当前目录，也接受显式仓库路径。运行框架命令必须先核对保存配方，静态入口将 JSON 放入高级展开项。实时预览仅在用户点击嵌入时加载，按项目和精确 SHA 过滤。

## 共用核心、旧归档与隐私边界

Skill 只定位打包的同一 CLI/核心；compat.py 保留旧 --repo、--project 和压缩导出调用。archives.py 从独立的命名登记读取名称、别名和固定 SHA，作为只读适配器恢复旧 reprise-selected-snapshot-v1；原始提交与独立视图 SHA 分别报告。读取登记不迁移或重写原档案。安装使用版本化本体目录和可验证指针，保留旧本体，避免修改正在运行的服务代码。

organize.py 在固定保护范围后创建完整恢复副本，逐项读回后才发布候选计划；选择再次核对文件签名、内容和保护范围，所有初始保护项保留。选择只写待执行回执，不删除源文件或内容库对象。存在排除项或未覆盖属性时明确报告恢复范围，不承诺完整应用环境。

metadata.py 使用标准库或 macOS 本地 API 保存与读回扩展属性；每个文件的属性合计上限 2 MiB，超限拒绝保存。旧文件夹版本未保存的属性不会补称已保存。ACL、文件系统标志和所有者尚未完整还原。

privacy.py 为 CLI 与界面提供同一可检查处理说明，默认项目与整理输出为摘要，完整清单按需展开。基础版本流程不调用可选 AI；AI 建议发送前说明输入范围。数据留存和宿主代理边界见 PRIVACY.md。

## 高级维护：完整性与占用账本

integrity.py 检查选中的文件夹版本；排队前固定完整 SHA，检查版本清单、payload 对象和内容指纹，不依赖源目录，不修改版本库。结果只覆盖该版本，不替代恢复副本的读回校验，也不证明独立介质或程序可运行。

storage_report.py 只遍历显式数据目录的元数据，不读取正文，不跟随符号链接或外部源路径；类别互不重叠，硬链接字节只计一次。文件逻辑长度、已分配块估计、文件系统空闲量分别报告，APFS 独占占用和可回收量未知。运行期间读取不是原子快照，读失败须返回部分报告。HTTP 检查复用可取消的持久任务，CLI storage 可以在不存在的数据目录上只读报告，不创建目录。

## 高级维护：备份与位置

maintenance.py 提供非阻塞共享/独占数据租约。Reprise 服务和正常写入持共享租约；backup.py 的离线备份持独占租约与旧 server.lock，避免复制活动数据。JSONL 清单和块级 I/O限制文件内容内存，复制后逐文件读回，并复核源目录变化。备份只覆盖明确数据根，外部来源从登记中报告而不遍历。

restore_backup 只写新数据根，重定位已知元数据字段并禁用服务器、任务和运行记录中的旧进程身份。用户说明与未知 JSON 原样保留，迁移差异和回执写新目标的同级目录。relocation.py 依据当前内容、已存文件夹版本或 Git 提交锚点核对来源；projects.json 保留稳定项目标识，旧归档 overlay 不写回。migrate 在源/目标读回与源变化检查后才原子切换登记，所有原文件和失败副本保留。

## 高级维护：删除版本与可重建环境

`version_deletion.py`、`content_lock.py` 与 `environments.py` 保留已有能力。删除是显式选定版本的独立操作，不是 `organize/select` 的自动副作用。第一次删除将自有库转换为 `reprise-snapshots.json` 目录和逐版本 refs：每个保留提交是完整目录树的合法 Git shallow root，原提交字节、完整 SHA 和有序 parent 头保持；原父版本已删除时显示缺失边界，不虚构连接。读取历史与归属使用目录，不依赖祖先遍历。旧客户端不支持这个受管库格式。

删除后的目录模式中，保存版本使用 `snapshot-transaction.json` 记录旧/新引用、目录和 shallow 边界。目录原子替换是提交点：进程退出后，下次打开历史会回滚尚未提交的引用，或完成已经提交的版本；恢复步骤可重复执行。内容 gate 隔离读者，未知记录或不匹配状态阻止自动修改。每轮完成或回滚回执单独保留，未引用对象仍作为诊断存在。只读 `verify` 不主动恢复；离线备份拒绝未完成的保存事务。子进程退出回归验证这些边界，不代表任意文件系统断电场景已经验证。

全内容库读写使用跨线程、跨进程可重入 gate；整个恢复期间持锁。删除计划绑定所有项目、引用、快照清单与对象库存；共同引用及未登记诊断闭包均受保护。替换库只复制所需对象，Git fsck 和每个保留版本的 SHA256/清单核验在切换前后执行。事务先持久记录，再交换目录；切换失败回滚，回收失败保留事务并要求明确重试。后台启动不自行删除；未完成事务阻止新快照和备份。整库重打包需要临时磁盘空间，尚未针对多 TB 内容库做性能验证；不能将小样本结果外推到长期大库。

环境身份由项目、源码完整 SHA、已保存配方、声明输入哈希、工具版本/可执行文件哈希及平台组成。只有历史源码中不存在的登记输出可删除；源码、输出和进程身份复核失败时保留。生成环境不是安全沙箱，命令能使用宿主网络与权限。系统库、环境变量、外部服务没有归档。捕获复用正在运行的环境时，不停止已有用户预览。备份恢复将环境标为需重建，并使旧删除计划失效。

降低主界面复杂度不删除这些实现、旧入口、原始媒体或诊断；它们按需展开，仍经过原有检查和明确确认。后续只有真实使用证据表明需要，才增加新的持久层、运行适配器或跨项目管理概念。

## 大历史的文件检索

文件检索按来源分组，每批最多 128 个完整 SHA，通过同源 `search-index` 接口读取名称索引。Git 来源批量读取提交头和准确的第一父差异，不逐个加载配方、检测、媒体和版本详情。根提交、空差异、重命名前后路径与 SHA-256 保留；浅历史缺少第一父对象时明确报告不完整，不改成根提交。文件夹与旧归档沿用各自既有的差异契约。图数据、父序和源仓库保持只读。底层批处理语义见 [Git diff-tree](https://git-scm.com/docs/git-diff-tree)。
