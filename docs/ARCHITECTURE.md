# 通用 Git 项目架构

## 目标与边界

Git 项目能被读取，与项目能够运行，是两个不同的能力。Reprise 先让任何可读的本地 Git 仓库进入统一数据模型，再根据该提交的文件证据确定运行和采集能力。项目名称、目录、路由和命令均不进入核心源码。

Git 是版本内容的来源；项目注册表记录本机路径和人工配置；运行目录是某一 SHA 的独立副本；证据是带来源的不可混用记录。列表相邻项不代表父子关系。

## 模块结构

```text
run.py / cli.py ─┐
                ├─ service.py ─ projects.py ─ git.py ─ 原仓库（只读）
web/ ↔ server.py┘       │              ├─ detection.py
                       │              └─ recipes.py
                       ├─ jobs.py ─ runtime.py ─ 独立历史副本 + 日志
                       ├─ workspace.py ─ 历史快照 / 显式关联存档 / 双侧文件比较
                       │             └─ processes.py → static_server.py / 明确批准的 argv
                       ├─ capture.py ─ browser_worker.mjs ─ 截图 / 录像 / 诊断
                       ├─ evidence.py ─ 人工资料 / 历史资料导入
                       └─ ai.py ─ 可选提案 → 校验 → 人工保存配置
```

### 1. Git 对象层

`Repository` 使用系统 Git 的 `rev-parse`、`for-each-ref`、`log`、`ls-tree`、`diff-tree`、`cat-file`、`status` 等命令，通过 argv 和 NUL 分隔传递结果。支持普通工作仓库、裸仓库、linked worktree、未提交的空仓库、detached HEAD、SHA-1 / SHA-256 仓库。对路径使用 filesystem surrogateescape，避免空格、Tab、换行破坏解析。

每个提交保留完整 SHA、真实 parents、作者、时间及引用。默认 diff 使用真实第一父节点；合并提交可选择其他父节点；根提交与空树比较。浅克隆缺失父对象时仍显示提交和现有证据，并指出差异不可读。历史实时从 Git 读取，不再依赖预生成的 61 项目录。

还原直接读取 Git blob，验证对象内容，写入新建的托管目录。不 checkout 源工作区，不修改源 index，不运行仓库 hooks / smudge 过滤器，不自动 fetch。子模块保留 gitlink 信息；LFS 指针明确标记。危险路径、越界符号链接、不可表示的文件和超限输出必须失败并说明，不能悄悄替换内容。

工作树状态在独立的只读 Git 元数据视图中计算：复制 index/sharedindex、HEAD 和影响内置转换的安全配置，原对象目录只供读取；最终 status 不加载源配置或 include，因此即使源配置并发新增 clean/process 驱动也不会执行。CRLF、working-tree-encoding 等内置转换保留。未执行的自定义过滤转换可能让文件显示 modified，返回状态明确说明这一限制。视图按内容哈希复用，保留在应用数据的 `git-status/` 私有目录。

### 2. 项目注册与能力识别

`ProjectStore` 只保存稳定项目 ID、规范化路径、显示名称和人工配方。HEAD 和 history 随时重新读 Git。识别缓存以仓库路径 + 精确 SHA 为键。`detection.py` 读取提交内的 manifests 和 HTML，返回识别信号、置信度、候选根目录、警告和能力。

无须能够识别框架，才能浏览仓库。未知类型仍有 history/diff/manual 能力。识别到框架也不代表它当前可运行；只有实际配方和运行结果能说明运行能力。Canvas 是绘图技术，单独出现不能证明项目是游戏。

配方优先级：当前完整 SHA 的人工配置 > 当前提交的 `.reprise.json` > 自动静态识别。提交里的命令型配方是未批准输入，必须在工作台核对保存。历史版本可以有不同入口和配置；执行任务前锁定 SHA 与规范化配方副本，避免排队期间 HEAD 或配置变化改写请求。

### 3. 运行适配与生命周期

运行适配器目前有 `static-web`、`command-web`、`manual`。适配器读取同一配方契约，持有独立副本、进程身份、就绪状态和日志。静态网页使用专用 loopback HTTP 服务，支持视频 Range、WASM MIME 和跨来源隔离头。命令型适配器按 install → build → start 执行 argv，端口由系统分配并传入 `{port}` / `PORT`。

运行进程使用新 session，停止时校验 PID 与启动身份。API 与项目预览使用不同来源，项目脚本得不到管理 API 的跨源读取权限。停止保留文件；没有自动清理、自动提交、自动推送流程。线程池限制任务并发，同项目由持久锁防止 CLI 与服务并行覆盖；服务重启识别已中断任务。

可信 Python 启动入口先等待进程所有权登记，再以 exec 执行目标 argv；短命令也不能抢先退出而丢失身份。各 install/build/start 阶段分别保留进程树记录，安装与构建结束后清理其后代，再进入下一阶段。观察器登记后代和会话；可信启动器在执行命令前注入随机所有权标记，macOS/Linux 从内核读取标记以追踪快速双重 fork、重新归属及独立会话的后代。只保留标记，不持久化其他进程环境。父进程退出不等于整树退出；停止前进行两次独立所有权扫描并再次核验身份，对顽固进程升级到 KILL，并确认结果。身份或清理无法确认时保存 `cleanup_failed`，接口报错，界面保留“停止未确认”与重试入口。尚在准备/启动的任务使用取消任务，不能通过停止接口制造先停止后启动的竞态。

静态服务器由可信绝对脚本通过 `python -I -S` 启动，不搜索仓库或继承的 Python 路径，并精确校验 loopback Host。进程跟踪用于生命周期管理，不能保证归因一个主动清除所有权标记且从未被观察到的恶意后台进程；这仍属于下面的容器/虚拟机隔离范围。

这些进程以当前本机用户权限运行。若要运行不可信仓库，需要后续容器/虚拟机 adapter；不能把“独立副本”叫作沙箱。现阶段明确的命令配置与执行动作承担授权边界。

### 4. 确定性采集与证据

采集输入是 `project_id + target SHA + base SHA + target recipe hash + effective base recipe hash + runner version`。两个版本分别使用各自的适配器、根目录、启动命令与就绪条件；路由、视口、操作、录屏和网络策略使用目标版本定义的同一组采集场景。基准配置缺失或未批准时拒绝执行并指出需配置的 SHA；缺资源保留诊断，不从其他版本回填。

浏览器从独立上下文启动，等待页面、fonts、图片 decode、媒体 metadata 与指定的 app-ready 选择器。全页采集先触发可见范围内的懒加载，再恢复位置；交互按有限步骤执行。PNG 保留像素尺寸；录像记录自己的宽高。HTTP 失败、脚本错误、缺图和阻断请求会降低记录状态，诊断截图不标成通过。

`network:local` 只允许当前运行实例来源，以及 data/blob；`allow` 是显式放宽的浏览器网络策略。捕获器不用 AI。成功缓存必须匹配全部采集输入且产物仍存在；失败和部分成功不会阻止重试。每次运行/失败的日志和产物独立保留。

人工证据复制到托管存储，明确标记 `source:manual / verification:user-supplied`，绑定用户指定的 SHA，并保留原路径和内容哈希。历史导入证据标为 legacy，保留原始采集元数据，不冒充新引擎重跑验证。只有具有相同场景/媒体类型/两侧 SHA 的资料才能被直观成对呈现。

### 5. 可选 AI 边界

模型适配器只接受有限的已提交清单、路径和差异元数据，只返回结构化提案。输出通过 `validate_recipe` 与文件依据检查，包含 provider/model、输入哈希和提示词版本。提案要求一次包含 zh/en 两种语言的标题、摘要和变化说明，缺失或超出限制即拒绝；提示词版本进入缓存键，旧版单语缓存不会被复用。提案不会自动保存、执行或变成验证证据。审阅后的版本说明由独立 notes 接口绑定完整 SHA；说明保存不批准配方，原始 Git 消息保留。连接配置在请求途中变化时，旧响应丢弃。当前实现兼容 Chat Completions 接口，可通过替换 provider adapter 接入其他供应商；旧原型里的 Codex 配置不被迁移或改写。

## 数据目录

```text
<application data>/
  projects.json                 项目注册 + version_recipes / version_notes（完整 SHA）+ 保存历史
  jobs/<id>.json                任务和恢复状态
  runtimes/<id>/runtime.json    进程身份与配置哈希
  runtimes/<id>/process-*.json  各阶段的进程树所有权及清理记录
  runtimes/<id>/source/         精确提交的独立副本
  runtimes/<id>/runtime.log     安装 / 构建 / 启动日志
  evidence/<id>/record.json     SHA、配方、来源、诊断、媒体元数据
  evidence/<id>/*               原始截图、录像、采集输入和日志
  ai/settings.json             本机私密连接配置
  ai/proposals/                 已校验但未自动执行的模型提案
  git-status/<hash>/             可复用的私有 Git 状态元数据视图
```

应用数据应放在源仓库以外。读取 Git、刷新列表、切换项目不创建预览副本。只有运行、采集、人工导入等具体操作才写相应托管内容。

## 版本配置与取消任务

人工配置只对保存时解析出的完整 SHA 生效。`HEAD` 前进后不继承上一提交的批准。已有 `recipe` 字段原样保留并通过 `legacy_recipe` 暴露为草稿，不再跨版本自动生效；用户可在指定版本载入并保存。清除某版本覆盖配置使用 `recipe:null`，保留保存历史后回退到提交配置/识别。

运行与采集使用持久取消请求和协作式检查，状态为 queued → running → cancelling → cancelled（清理失败则 failed）。排队取消释放项目锁；运行中取消覆盖快照、安装/构建、服务就绪、采集锁等待及浏览器阶段。只停止具有匹配进程身份的自有进程；部分输出与日志保留。任务完成后取消为幂等操作，不停止已经交付的预览；此时使用运行实例的停止接口。CLI 与服务共享取消请求。

每份任务记录独立校验；损坏 JSON、结构、编码或读取错误通过 `job_warnings` 显示，跳过该条但保留原文件，不阻止其他任务和工作台启动。

### 命令入口与网页

`reprise .` / `open` 从当前目录定位仓库，检查数据目录不位于源仓库内，再启动或复用服务。启动通过可信绝对 `server_entry.py`、`python -I -S` 和托管工作目录，不搜索项目模块。复用检查 PID 启动身份、健康接口实例随机标记与数据目录；不按端口猜测服务。`--no-browser` 返回 JSON，`shutdown` 通过带 token 的本机接口取消任务并停止预览，无法确认清理就报错。

`web/` 是通用核心唯一前端编辑源。当前 `index.html` 只加载 `graph-layout.js`、`locale.js`、`live-copy.js`、`live-focus.js`、`live-parity.js`、`live-features.js`、`live-updates.js` 与 `live.js`；样式来自 `base.css` / `live.css`。旧 app/shell/Paper Grid 文件与视觉档案保留，但不在当前页面执行。不在核心内保留具体项目路径、固定版本或用户模型设置。

## 0.3.0 版本工作台

Git 关系图的节点、父边、参考线、轨道复用、避碰、像素投影及换仓库回归要求，统一见 [Git 图实现契约](GIT-GRAPH.md)。视觉调整不能改写真实父关系，筛选不能删掉关系节点。

`workspace.py` 提供通用历史快照、显式关联存档、比较来源选择与双侧文件文本。`web/live*.js` 和 `graph-layout.js` 是当前正式界面，读取 `/api/workspace/*` 和原有版本、运行、资料 API。启动 URL 中的项目标识决定上下文；不会通过其他项目切换入口改变启动仓库。旧 `app.js` 和 Paper Grid 视觉档案继续保留。

关联存档先验证共同 Git 提交，再保存本机注册信息；按完整 SHA 去重，保留每条版本的读取来源。目录筛选只影响存档显示，不删除 Git 对象。路线只依据真实 parents，独立记录显示分隔说明。媒体以完整 SHA 和采集场景匹配；手工资料没有场景元数据时不会自动伪造成前后对照。AI 提案和运行配置仍须单独明确保存。

## 资源预算与维护

不增加前端框架、数据库、常驻 Node 服务或 Python 第三方依赖。管理服务只有 Python HTTP 服务和按需启动的任务/预览；Node 与浏览器仅在采集时使用。空闲取消观察器阻塞等待，存在可取消任务时才每 100ms 检查跨进程取消请求。

历史最多读取 64 个不同 tip，每个 tip 最多 2000 条，超限保留父 SHA 边界并返回警告。每个 tip 一次 Git 遍历；已加载且祖先完整、数量未超限的历史直接复用。不能改成所有分支共享一个全局数量限制，从而丢掉冷门支线。快照指纹包含说明、引用及存档显示集合的变化；不提供整个仓库原子事务的保证。

前端按完整 SHA 建立提交索引。详情缓存最多 128 项，当前选中、比较两侧与预览基准保留；逐版本文件路径独立保存，淘汰详情不会破坏文件搜索。重复搜索复用已读取路径，刷新清空以恢复缺失对象。翻译表只编译一次，文本缓存最多 512 项；局部 DOM 更新只翻译变化区域。图片变化区域缓存最多 64 项。任务状态不变时不重建详情页面。

证据 HTTP 路径只提供该记录登记的 items；采集输入、所有权记录与日志仍保留在本地，不随媒体地址公开。视频和大文件按块传输，支持 Range；不把整份媒体读入内存。

当前图仍渲染整个已加载集合，文件搜索首次仍需读取各版本差异，保留的磁盘证据没有自动清理。这些是明确的规模边界。只有实际长历史测量证明需要时，再加入虚拟列表或索引数据库；保持完整 SHA、全部有序父边和历史来源契约。

`tests/workspace-cache.test.cjs` 验证缓存淘汰后搜索与比较仍正确；Python 与真实浏览器回归验证业务/安全边界。CI 配置覆盖 macOS/Linux、最低 Python 与另一版本，以及全新安装；配置存在不等于远端执行已通过。
