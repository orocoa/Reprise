# Reprise sharing brief

October 24, 2026. For the unpublished 0.8 local candidate. These materials have not been posted and no trial invitations have been sent. [中文](SHARING-BRIEF.md) · [Ready-to-edit copy](SHARING-COPY.md)

## One task

**Save a draft before your next change, then find it later by how it looked.**

Someone editing a local website keeps A, tries a change and saves B, then recognizes A in the visual workbench and retrieves a copy to keep editing. The current project stays unchanged. Saving files and capturing a picture have separate results. Unsaved drafts cannot be retrieved.

The primary delivery is a lightweight source Skill with scripts, a fixed local core and a visual workbench. The agent reuses available tools and fills missing dependencies through official methods and normal authorization. “Open” only opens the workbench. It does not save or import the agent's current directory. Use the client's actual Skill selector; the product name does not establish a universal @ alias.

## A 42-second demonstration

Use a nonsensitive synthetic HTML project. Label the recording “0.8 local candidate.” This is a planned storyboard, not an existing video or a 42-second setup guarantee.

| Time | Action | Narration |
| --- | --- | --- |
| 0–5 s | Show A in the editor and browser before changing spacing. | “I'll keep this version before asking AI for another change.” |
| 5–13 s | Select the Skill through a verified client entry. Ask to save “Before changing spacing”, including its screenshot. Show both actual results. | “Save this draft and how it looks.” |
| 13–22 s | Make a visible change to B. Save “After changing spacing”, including its screenshot. | “Try another version and keep that too.” |
| 22–27 s | Select the Skill and say “Open.” No new save occurs. | “Open Reprise when I want to revisit it.” |
| 27–33 s | Recognize A by its picture in the gallery. | “Find the draft by how it looked.” |
| 33–42 s | Recover A into a new folder and make a small edit in that copy. Keep B visible. | “Take out a copy and keep editing. The current version stays too.” |

Use real actions and matching-version screenshots. Keep the unedited evidence if waiting time is cut, and disclose the edit. A missing picture stays missing. Do not expose private paths, accounts, keys or client materials.

## A bounded trial

Use the [same 5–8-person task sheet](PRIVATE-TEST-TASKS.en-20261024.md), with real tasks on nonsensitive project copies. Observe how participants currently find drafts before explaining why they might need Reprise. Separate setup time, task time, help, errors and abandonment.

The two-draft exercise checks basic operation. During the following 14 days, do not remind participants to save. Record actual opportunities, voluntary reuse and natural draft-retrieval events. Lack of an opportunity and loss to follow-up remain unknown outcomes, not failures or successes. The sample is a qualitative effort limit, not a market estimate.

Pause affected paths for incorrect recovery, source changes, unrelated imports or wrong-picture success claims. Pause trial and sharing if the candidate package and demonstration do not match. Fix observed onboarding blockers in at most one focused pass. If eligible people with another real opportunity still prefer their existing method or do not reuse Reprise, retain it as a personal tool and stop broadening it. Do not add features merely to postpone that decision.

## What can be said now

The primary delivery is a source Skill and scripts. It reuses or prepares host dependencies through normal authorization rather than bundling another Python/Node/Git/browser installation. Using the Skill does not require obtaining an Apple Developer certificate.

An unmodified source Skill passed on this Mac using existing Codex Python/Git/Node/Playwright and Chrome: doctor, two real draft pictures, byte-checked CLI recovery, Chinese/English opening and normal shutdown. No dependencies were installed or downloaded and no global configuration changed. This is evidence for that existing environment and CLI/synthetic fixture only, not automatic setup on a missing-dependency Mac, cross-agent screenshots, native import or independent adoption. Doctor checks base tools and package integrity; screenshots required separate actual captures.

The complete runtime test bundle was withdrawn after its downloaded first launch was blocked. Historical diagnostics remain records rather than setup instructions.

The earlier core regression run retains one unexplained task-wait timeout; unchanged single-test and module retests passed without turning the full run into an all-pass result. Record targeted Skill-instruction/packaging checks and the new source ZIP identity in their own receipt, without borrowing old candidate totals. See [setup and dependencies](AGENT-SKILL.md#english). WorkBuddy/TRAE native operations remain deferred; independent adoption and repeated use remain unverified.

## Is open-source sharing worthwhile?

Source sharing and a small targeted trial are reasonable. Broad promotion and expanding platform support lack independent-use evidence. MIT helps people inspect and reuse code; Stars indicate interest or appreciation, not task completion or repeated use.

There are substitutes: [Cursor checkpoints](https://cursor.com/docs/agent/overview#checkpoints) and the [design-history project](https://github.com/kingermayank/design-history), as well as Git or numbered folders with screenshots. These comparisons are based on documentation, not hands-on competitor tests. The remaining hypothesis is whether connecting a recognizable picture to the correct files and a recoverable copy saves enough effort to justify setup and proactive saving.
