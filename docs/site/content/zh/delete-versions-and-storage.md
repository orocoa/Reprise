# 删除旧版本前，先看会失去什么

**版本：0.8.5。样本教程可停在预检；实际删除需明确核对并确认。**

任务：区分删除历史状态、移除本机展示、释放依赖和停止预览。受管文件夹快照可以删除保存内容；外部 Git 和历史归档只能从 Reprise 移除，源历史保持。

## 当前界面的操作范围

选中一稿，点击「删除」，核对范围后确认。普通留稿删除其保存状态、专属运行副本和对应画面；Git/归档的「从 Reprise 移除」删除本机登记与受管附件，保留源提交和原归档。原文件夹、外部备份和已有恢复副本保持。只有已登记并验证的生成环境才能选择「仅清理环境」；没有可清理环境时明确禁用。运行中的版本会先提供停止预览并重新核对的入口。

内存和磁盘分别处理：运行预览窗口中的「停止预览」结束此实例的进程，保留版本和文件；「返回版本」只关闭弹窗。设置里的「停止 Reprise」停止该数据目录的服务与预览。释放环境删除已验证的依赖产物，主要影响磁盘，不能保证电脑整体内存或速度改善。

下方 CLI 联合删除针对保存内容，会保留画面和运行副本；不要把它与界面单版删除附件的范围混为一谈。

## 前提

先按[认版与恢复](find-compare-restore.md)核对完整 SHA。以下 `DATA`、`PROJECT` 与 `FULL_SHA_*` 使用同一次样本的真实值。查看预检不等于授权执行；样本中不含真实个人资料。

## 默认步骤：比较影响，不执行删除

1. 在工作台打开「整理版本」，选一稿，使用「查看此版」检查其文件与证据，再返回。
2. 阅读完整 SHA、失去的路径、元数据、独占内容、仍共享内容和保留版本数量。
3. 加选另一稿，重新看整组选中版本的影响。联合回收不能把两个单版数字直接相加。
4. 停在影响说明，保留确认框未选中的状态。

CLI 预检如下：

```sh
python3 "$REPRISE_ENTRY" --data "DATA" version-delete-plan PROJECT --sha FULL_SHA_A
python3 "$REPRISE_ENTRY" --data "DATA" version-delete-plan PROJECT --sha FULL_SHA_A --sha FULL_SHA_B
python3 "$REPRISE_ENTRY" --data "DATA" storage
```

预检会留下计划与状态信息，但不删除版本。最后一条只统计选定数据目录的存储，不扫描整个电脑。

## 怎样读数字

| 字段 | 应当理解为 | 不能理解为 |
|---|---|---|
| `unique_content_bytes` | 整组选中版本独占的原始内容字节，按内容计一次 | 删除后一定释放的磁盘空间 |
| `shared_content_bytes` | 仍被其他版本、项目或诊断引用的内容 | 可以重复回收的字节 |
| `store_bytes_reclaimed` | 执行前后主对象库普通文件长度的变化，可为负 | 全数据目录净收益 |
| `allocated_bytes_reclaimed` | 已分配块统计的变化 | APFS 共享块的真实独占量 |
| `volume_free_delta` | 两次观测之间的卷空闲变化 | 仅由这次操作造成的收益 |

`storage` 的 `reclaimable_bytes` 未知时应保留未知，不能用 `logical_bytes` 替代。环境预检的 `output_bytes` 也不等于保证可释放量。

即使 `unique_content_bytes` 为零，该版的目录组合、名称、元数据和完整历史状态仍会失去。压缩、索引、临时重打包空间、保留回执与其他进程都会影响前后数字。本文没有填入任何未核对的实测收益。

## 另行明确操作：实际删除

仅在你另外决定执行、已读过本次计划并接受历史损失时，才使用计划返回的真实 `PLAN_ID`：

```sh
python3 "$REPRISE_ENTRY" --data "DATA" version-delete PROJECT --plan PLAN_ID --confirm
```

这条命令会执行删除，**不属于默认教程步骤**。执行会重新检查计划，并在全库验证剩余内容后回收原对象库。原件、已有恢复副本、截图、运行副本、日志和孤立诊断仍保留；它不是安全擦除。

## 结果与失败限制

默认路径的结果是一份可审阅的计划，版本仍在。若另行执行，应核对删除回执、保留版本的检查结果与上述不同存储口径，并实际恢复一个保留版本到新目录确认所需内容。

预检后对象、引用或快照变化会使计划失效，应重新预检。未完成回收事务可能阻断新保存与备份；按错误提示处理并保留诊断，不手动清掉事务目录。空间不足时保留原库，不先删原库腾空间。首次删除会改变受管库格式，旧客户端不兼容，后续需要 0.7.0 或兼容版本。当前没有多 TB 压力测试结论。
