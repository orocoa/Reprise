# Reprise 线框动画 · 最终确认规则

本文件以 `source/browse-motion.js` 的冻结实现为准。时间轴在 `motion/timelines.json` 中，实际动画片段在同目录中。用户在 2026-10-08 最终确认必要时允许线条并入真实边框。

## 时间与阶段

| 阶段 | 冻结值 |
| --- | --- |
| 线框位置 / 长度 | `620ms`，`cubic-bezier(.22,.68,.18,1)` |
| 目录文字 | 延迟 `620ms`，`180ms ease-out` |
| 新内容 | 延迟 `620ms`，`200ms ease-out` |
| 粗细与颜色 | 到位后 `200ms ease-out` |
| 多余横线退场 | 独立 `160ms ease-out` |
| 新增横线 | 位于自己的终点，延迟 `620ms` 后用 `200ms` 出现 |
| 预览选项展开 / 收起 | `420ms`，同一缓动，高度由实际内容决定 |
| hover | 直接黑白反转，无颜色渐变过渡 |

线条持续覆盖内容淡入阶段，直到整段结束，避免末帧撤掉线框后又换一套边框。视觉主线是位置连续变化，不加入弹跳、拉伸回弹或额外绕行。

## 起点与终点

测量实际渲染出来的边框位置、长度、颜色和粗细。移动按真实起终点进行；同一坐标的线保持原位。滚动列表只采集其可视范围中的线条，不补齐视口外条目。

全宽目录进入详情时，原目录本身的宽度、行高、列表高度与内边距连续改变，到位后出现标签和详情。这是最初录屏中用户认可的基准动作；保留 `browseMotion` 的实现。

跨页面与详情切换由 `viewMotion` 承接真实边框。横线默认一对一配对，保持次序；多余源线在相邻目标之间独立退场，额外目标线在自己的位置出现。位置与长度先到位，之后才调整粗细、颜色和内容。

## 竖线与必要融合

- 详情到管理：已有内部竖分隔线平滑向右推到管理页实际右侧边框，途中保持可见。到位后只留下已有外框，通过覆盖区域裁切自然收拢，不加融合闪光或短暂加厚。
- 列表到管理、管理到全宽列表：两端都没有内部竖线，不创建临时竖线。
- 两端都有内部竖线：连接实际位置；终点不变就不额外横扫。
- 只在目标存在的竖线：在目标位置随内容出现。
- 其他确实需要消失且没有真实合并边框的线：在自己的位置退场。

必要融合的终点必须是确实存在的布局边界。不能因为目的页面线少就将多根横线压向同一处，也不能凭空创建竖线制造运动。用户后来确认的竖线并框规则优先于早期“任何线都不融合”的问题反馈。

## 中断与可访问性

连续点击从当前画面中的真实线条坐标继续，不跳回上一个动画的起点或终点。视口变化或坐标空间改变时清理覆盖层，不能遗留透明层、`inert` 或忙碌状态。只让受动画影响的内容暂时不可操作，保留可用的导航路径。

系统启用减少动态效果时直接呈现最终布局。展开、关闭和返回保留用户所在上下文，窄屏与空内容也能找到原来的入口。

## 复用实现

`browseMotion` 负责全宽目录变成左栏，`viewMotion` 负责跨页面与详情边框过渡；它们使用 Web Animations API。`reuse/` 中提供冻结引擎和独立示例，`source/app.js` 保存原集成方式。

接入其他产品时把页面、目录、横线和详情区域的选择器映射到新组件，保持测量真实边框、可见裁切、直接插值、分阶段呈现、中断承接和覆盖层清理。不要复制原项目的 SHA、标题、路径、服务器地址或 Git 操作逻辑。

验收时核对：起终点准确、没有额外路线、文字在最终位置出现、右侧并框无突兀变粗、连续点击无跳回、减少动态效果可用、内容与布局在动画结束后仍一致。
