# Reprise / 倒带

以 PersonalWeb 历史版本为示例的本地 Git 版本管理 Demo。只有 **版本浏览** 和 **版本管理** 两页。先看相对上一版的区别和真实截图，点击后才从 Git 准备环境；运行副本清理后仍可重建。复用已有 Git 存档、项目启动脚本、Node 与 Python，没有安装新的容器平台或模型服务。

地址：<http://127.0.0.1:51581/#versions>。

## 两页的作用

- **版本浏览**：首次进入显示与版本管理一致的全宽行式目录，包含当前 Git 和版本搜索；选择栏只显示版本名称，日期保留在详情中。选中项用细黑框，悬停选项反转为黑底白字；导航选中时仅将文字变黑加粗。选择后先隐去文字，目录线框在 620ms 内收向左栏，到位后再显示左栏文字与右侧完整详情；系统选择减少动态效果时直接切换。历史版本直接显示变化说明、缓存截图、打开此版本与重命名入口；“对比上一版 ↗”打开并排弹窗，按当前所选页面、语言和视口匹配上一版；不存在对应预览时明确标注。预览栏使用“预览 ＋”，展开行式选项，选择后自动收起；窄屏对比上下排列。当前 Git 直接展示变更文件与提交入口。
- **版本管理**：依次展示已下载版本环境、可选 AI 和 Git 内容，只保留状态、空间和操作。环境可打开、停止保留、逐份删除或全部删除；默认同时运行一个版本。删除前检查内容与 Git 一致；有未保存改动时保留环境。Git 可以导出备份，界面与 API 都没有删除 Git 的操作。

动画验收基准：用户提供的 `Screen Recording 2026-10-08 at 16.46.18.mov` 中「全宽目录进入版本详情」的效果。保留 620ms、`cubic-bezier(.22,.68,.18,1)` 的线框运动，线条到位后再用 200ms 淡入内容。版本浏览、详情、当前 Git 与版本管理之间的往返统一沿用这一节奏；横线的位置和长度连续过渡，并与竖线同速衔接。线条默认对应一个明确终点；多余线条独立淡出，新增线条到位后独立淡入。必要的布局收拢允许线条并入真实目标边框：版本详情进入版本管理时，内部竖分隔线与横线同步向右推进，并入最右侧边框后呈现内容。全宽版本列表与版本管理之间没有内部竖线，不额外生成竖线；横线继续直接平滑过渡，避免多根横线无必要地挤向同一个终点。线条到位后再调整粗细与颜色。内容淡入结束前保留到位的横线，不能在末帧换一套线。连续点击从当前画面继续；减少动态效果时直接切换。

Git 存档、说明、截图、标签、环境配方与验证证据不会被运行副本清理入口删除。本 Demo 没有删除 Git 存档的入口。

历史版本详情中的“重命名”可以修改显示名称；列表、搜索、详情、上一版对比和对应环境标题同步使用新名称。名称按稳定版本 ID（当前为完整 SHA）保存在独立的 `data/version-names.json`，刷新页面或重启服务后继续保留。原来的名称仍可搜索，也可在重命名弹窗中恢复原名。重命名只改变本地显示名称，不修改 Git 提交信息、SHA、标签、目录、截图或缓存说明。

名称需为 1–80 个 Unicode 字符，去除首尾空白，拒绝换行与隐藏控制字符，按纯文本显示。`POST /api/rename` 接受 `{ "version": "完整版本 ID", "title": "新名称" }`；`title: null` 恢复原名。此接口沿用本页面 token 与 Origin 校验，只写固定元数据路径。Git 导出配置也包含自定义名称。

## 怎么理解不同版本

61 个存档包括 **6 次原 Git 提交、13 个恢复的源码快照、42 个发布包**。原提交按照真实父提交比较；恢复的源码按上一份源码快照比较；发布包按上一份发布包比较。恢复来源和原始时间保留，不把三类来源拼成虚构的一条原始提交历史。

## 自动化与可选 AI

Git 提交、还原、启动、停止、资源管理和缓存预览是程序核心，当前运行不依赖模型或 API key。“打开此版本”恢复为必要入口：准备完成后直接进入真实运行副本；已运行的版本显示“进入此版本”。管理页继续提供打开与结束体验。

最终架构支持两种方式：默认无 AI 模式使用 Git 差异、路径/文件类型规则和项目采集配置；可选 AI 模式辅助归纳变化与推荐预览位置。两者共用相同的 Git、运行、采集和缓存流程。未配置 AI、关闭 AI 或 AI 请求失败时，基础功能应完整保留。AI 结果必须关联真实文件差异和存档，不能决定 Git 提交、执行任意启动命令或生成冒充真实页面的媒体。

自动截图/录屏需要明确页面路由、视口、语言、等待条件及操作步骤；非视觉修改使用文字/文件依据。无法匹配规则时提示补充采集配置，允许人工校正。当前 61 份存档的说明和证据计划经过人工核对；自动采集调度尚未实现，不把已有缓存称为全自动生成。可选 AI HTTP 接口现已实现，默认关闭且未配置真实提供方。详细设计见 [自动化与 AI](docs/AUTOMATION-AND-AI.md)。


## 可选 AI 接口 · 2026-10-08

在 **版本管理 → 可选 AI → 配置** 填写兼容 Chat Completions 的服务地址、模型与密钥，启用后保存；“保存并测试连接”发送真实请求，成功才显示连接成功。未填写、关闭或服务失败时继续使用基础功能。模型由用户指定，没有强制默认服务。

启用后，版本页提供“AI 分析”按钮：只发送已核对的变化说明与 Git 文件清单，不发送源码或媒体。结果包含摘要、变化和待核对的预览建议，显示实际模型、来源和时间；按版本、基线、输入与模型缓存，保持原说明和真实预览。浏览、提交、打开版本不会自动调用 AI。

密钥仅保存在被 Git 忽略的本地配置文件，权限 0600，API 不回传密钥。当前已用独立模拟 HTTP 服务验收保存、真实请求路径、成功/失败状态、分析、缓存与关闭回退；用户自己的提供方仍待填写与实际连接验证。详细接口、数据范围与测试说明见 [自动化与 AI](docs/AUTOMATION-AND-AI.md)。


### 项目与界面语言

左上角名称从当前源项目识别：优先使用 `package.json` 的 `displayName` / `productName`，否则使用项目文件夹名称。`[ 中 / EN ]` 切换界面语言并保留选择；自定义版本名称、原始版本说明、文件路径和媒体内容保留原文。

管理页依次显示“已下载版本环境”、可选 AI、Git 内容。环境名称复用版本浏览中的同一名称来源，按版本日期排序。当前 Git 直接显示文件变更，列表下方可提交变更或查看当前 HEAD 对应的最近提交；右侧打开入口启动当前工作区的现有只读开发预览，包含未提交的页面改动，不修改或提交源文件。
