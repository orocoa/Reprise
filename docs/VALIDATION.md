## 本次重构

旧版是一个围绕已有 PersonalWeb 存档和人工截图目录的原型。旧服务、原仓库、61 个历史版本、原截图/录像及此前 QA 文件都保留。新源码位于 Reprise 自己的目录，旧版文件不参与新核心的执行。

新服务默认端口为 `51582`；旧原型仍使用原端口 `51581`。本次本机验收通过 `--data work/reprise` 使用独立数据目录。核心代码和 API 不包含 PersonalWeb 路径、SHA 或路由映射。

已有预览通过显式迁移工具进入统一证据契约：

```sh
python3 scripts/import_legacy_evidence.py \
  --data /path/to/reprise-data \
  --repo /path/to/archive.git \
  --catalog /path/to/exported-catalog.json \
  --media-root /path/to/original/previews
```

该工具只复制传入本地目录里的文件，校验提交是否存在，保留旧元数据并标记 `source:legacy`。不会修改、删除原文件，也不会把旧预览说成新引擎重跑的结果。61 个存档已全部导入；普通源仓库只接收它实际包含的提交。

## 目前明确的边界

本机宿主支持 macOS/Linux，Windows 进程与文件锁适配尚未实现。输入是已有的本地 Git 仓库，不代替远程账号登录和 clone。导入不初始化子模块、不下载 LFS、不更改原仓库 Git 设置。

原生应用/原生引擎的窗口自动采集、容器、远程 CI 和设备农场还没有实现；它们目前使用手工证据或 Web 导出路径。无法自动推断项目的私有服务、凭证、游戏存档、随机种子与所有交互状态。配方必须指定要观察的场景。

为了保持本地服务可响应，读取与采集有大小/时间上限：Git 单次输出默认 32 MiB，快照默认 4 GiB，手工单文件 512 MiB，浏览器全页图片限制 100M 像素/40,000 CSS px 高度。达到上限会明确失败并保留诊断，历史浏览仍与运行能力分开。外部资源会受网络策略影响；私有服务需显式配置。

这些边界不会被 AI 输出覆盖。新增适配器必须保持同样的版本身份、配置校验、进程归属、失败诊断和证据来源契约。
