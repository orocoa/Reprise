# 本地版本生命周期 · 0.8.5

目标是保存本地项目的版本、看懂变化、取回需要的一版，并在删除时知道会失去什么。使用独立样本核对范围；样本脚本不读取或迁移真实资料。当前界面提供受管版本删除、只读历史的本机移除和环境释放，见[删除与资源说明](site/content/zh/delete-versions-and-storage.md)。本页 CLI 联合删除仅处理保存内容，保留附件，与界面单版删除范围不同。

## 默认体验：保留全部版本

默认教程只看、比较和预检，保留全部样本版本与环境。现有样本可直接复用，无需为重新展示再创建一套。工作台具备明确确认后的执行能力；停在预检是教程步骤，不是全局只读模式。

保留三版供自己操作：`python3 scripts/prepare_lifecycle_demo.py --to /new/path/reprise-interactive`。它建立三份真实可运行环境并停止预览，保留全部历史版本；按 `summary.json` 中的 `open_command` 打开。可选 `--capture` 使用已安装的 Node/Playwright/Chromium 为精确 SHA 采集截图，默认不联网安装浏览器依赖。

1. 在版本列表依次查看「初稿」「第二稿」「当前稿」，从页面颜色、标题与阶段说明认准每版；截图必须属于所选完整 SHA。需要实际运行时，由用户主动启动并区分运行证据与静态截图。
2. 打开「整理版本」，选一版后「查看此版」，再返回检查选择是否保留。对比单选和多选的删除预检，查看独占内容、仍共享内容及保留版本数量。
3. 阅读会失去的路径、元数据和完整历史状态。即使内容仍被其他版本引用，也不能把“独占字节为零”理解为“没有损失”。停在影响说明，不勾选删除确认、不执行删除。
4. 查看已准备环境的状态与重建记录，区分源码、依赖产物和外部工具；默认教程保留环境。环境释放与后续重建是另行选择的执行流程，条件见下方「旧环境按需重建」。

这条体验应回答：能否选对旧稿、能否理解取舍、遇到缺失截图或重建条件时能否知道下一步。它不能单独证明真实资料的空间收益、长期重建成功率或用户愿意重复使用。

## 开发测试：会删除合成版本

`scripts/demo_version_lifecycle.py` 是会实际删除合成版本的开发回归脚本。它生成三个网页版本和另一个共享素材项目，真实启动前两版并核对 HTTP 内容，联合删除前两版后恢复剩余版和共享项目。需要验证这条执行路径时，用 `--to` 指定尚不存在的新目录：

```sh
python3 scripts/demo_version_lifecycle.py --to /new/path/reprise-lifecycle-test
```

这个脚本不用于保留三稿的默认交互体验，也不读取真实项目。`summary.json` 与 `commands/` 保留每步结果；输入在 `inputs/`，源文件夹和运行副本也保留。HTTP 与恢复字节核对不冒充浏览器截图、依赖重建或独立备份验证。删除、保留内容核验与环境重建的隔离回归结果，应按各次测试的源码和实际覆盖范围分别报告。

## 明确确认后的执行路径

打开同一数据目录的合成项目，在顶部「整理版本」选择一个或多个版本。可先「查看此版」检查文件、精确绑定的截图或运行，再返回保留的选择。删除影响显示完整 SHA、失去的独占文件内容、仍共享内容及全部受管库保留数量。即使独占字节为零，该版的目录、文件名、元数据和组合状态也会丢失。

确认后只删除所选受管快照；外部 Git 提交和旧归档不能从这里删除。执行在全库验证剩余内容后才回收原对象库。原件、已有恢复副本、截图、运行副本、日志和孤立诊断保留，因此不是安全擦除，也不等于所有副本都消失。

CLI 与 Skill 使用同一实现：

```sh
python3 run.py --data /path/to/demo/reprise-data version-delete-plan PROJECT --sha FULL_SHA_A --sha FULL_SHA_B
python3 run.py --data /path/to/demo/reprise-data version-delete PROJECT --plan PLAN_ID --confirm
```

预检之后任何对象库存、引用或项目快照变化会使计划失效。切换失败回滚原库；回收中断保留事务，明确重试同一计划才能续办。新保存与备份在未完成事务期间阻断。故障诊断保留，不为再次演示清掉失败目录。

## 存储数字

### 不删除也能做的更准确估算

在删除预检中点击「模拟打包，更准确估算」，或先创建删除计划，再执行：

```sh
python3 run.py --data DATA version-estimate PROJECT --plan PLAN_ID
```

模拟不会替换当前内容库，也不会调用版本删除或环境释放。它分别计量保留全部版本的重新打包结果、移除选中版本后的打包结果及一次重复结果，核对数据流校验和。压缩数据流计量后丢弃于内存流转中，不创建整份 pack 文件；仅保留对象 ID、元数据和诊断报告。额外记录的占用会单列，计划与任务记录另有少量开销；不会自动清除这些记录。

「版本库文件预计减少」把压缩包、索引和版本元数据一起计算，接近实际替换库的文件长度变化。它仍不等于系统卷将增加多少空闲。分配量根据当前卷的分配单位建模，不覆盖目录占用、APFS 克隆/共享块、快照、文件系统压缩和其他进程。模型为负时明确显示增加；收益拆解不把已有库的压缩收益全部归因于删除所选版本。

两次打包差异是可重复性观测，不能称作真实删除误差或统计置信区间。本轮另建并校验保留库，比较其文件长度和分配量，得到的是「对照构建误差」。由于未删除原版本，真实删除误差和卷空闲误差均保持未知。超过 2 GiB 的包对索引长偏移表采用保守结构上下界。估算依据明确 Git 版本、固定打包参数与当前库布局；库、配置或工具变化后须重新预检。

打包规则参考 [Git pack-objects 官方文档](https://git-scm.com/docs/git-pack-objects)。共享块限制参考 Apple 的 [About Apple File System](https://developer.apple.com/documentation/foundation/about-apple-file-system)。分配空间区间是本项目的模型推导，不是这些文档对回收量的保证。

| 字段 | 含义 |
|---|---|
| `unique_content_bytes` | 整组选中版本独占的原始内容字节，按内容只计一次 |
| `shared_content_bytes` | 删除后仍由其他版本、项目或诊断引用的内容字节 |
| `store_bytes_reclaimed` | 回收前后主对象库普通文件长度的减少，可为负 |
| `allocated_bytes_reclaimed` | `st_blocks × 512` 的减少；APFS 共享块下不是独占量 |
| `volume_free_delta` | 当时卷空闲变化，也受其他进程与文件系统影响 |

联合删除不是逐版收益之和。替换库重打包会改变压缩与索引成本；首次操作还可能压缩旧松散对象，所以库减少也不等于独占内容量。报告不计算回执、仍保留运行副本和其他数据的净总成本。完整过程需要临时空间；磁盘不足会保留原库和诊断，不先删原库腾空间。

## 旧环境按需重建

已保存并批准的 `command-web` 配方可以声明：

```json
{
  "environment": {
    "outputs": ["node_modules", "dist"],
    "inputs": ["package.json", "package-lock.json"],
    "tools": ["node", "npm"]
  }
}
```

这是运行配方的可选字段，仍需完整的 install/build/start 命令与检查条件。生成目录必须在历史源码中不存在；所有写入的生成目录应明确声明。输入来自已存版本，工具记录版本和可执行文件哈希。首次实际构建并成功启动后才有重建记录；停止运行、确认源码和输出未变化、核验进程及工具后才能释放登记产物。

```sh
python3 run.py --data DATA environments PROJECT
python3 run.py --data DATA environment-check ENVIRONMENT_ID
python3 run.py --data DATA environment-release ENVIRONMENT_ID --confirm
python3 run.py --data DATA run PROJECT --sha FULL_SHA
```

最后一步会在需要时重新构建。释放不删除源码、锁文件、配方、日志、截图或失败尝试；系统工具和全局缓存也保留。新增数据库、修改输出、共享硬链接、活动进程或缺少 `lsof` 检查会阻止释放。pnpm 等共享硬链接布局目前可能被保守拒绝；不会直接删除全局 store。

命令以当前账户运行，不是沙箱。安装依赖可能联网；`network:local` 只限制浏览器采集。系统库、宿主环境变量、外部服务和未来包源没有归档，所以“曾成功重建”不是永远可运行的保证。普通静态页面不需要托管环境也能运行。

含外部解释器链接的 venv 不能通过现有自包含备份边界；先显式释放已经核验的环境后可再备份。备份不会静默省略输出。恢复的环境标记为需重新构建，旧产物仍保留，旧删除计划必须重新预检。

## 兼容与当前限制

- 首次明确删除将 Reprise 自有库转为逐版本目录与合法浅根，保留存活完整 SHA 和真实父引用。已删除父版作为缺失边界显示；不能据此伪造差异。旧客户端不支持该受管格式，请用 0.7.0 或之后的兼容版本访问。
- 源 Git 仓库保持只读；普通文件夹 `.git` 默认排除，不能当作完整源 Git 历史备份。旧名称归档保留原适配器。
- 去重以文件完整字节为单位，不是块级去重；微小修改的大文件可能新增整份内容。运行目录与包管理器缓存没有跨环境共享去重。
- 已保存的每版目前需要显式记录；没有后台自动快照、云同步、全盘清理或内存优化。
- 删除会对全部保留版本读回校验并重打包；当前没有多 TB 压力测试。文件还原通过不代表应用已运行成功；同盘历史不是独立介质备份。
