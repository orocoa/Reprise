# Reprise 当前产品简报

2026-10-26 · Reprise 0.8.1 现行范围。文件夹留稿、版本图片与已有 Git 路线共用本地工作台。

服务正在用 Agent 或编辑器反复修改本地网页、希望凭画面认出已保存旧稿并取回的人。主线是：**Agent 接入 → 修改前留 A → 修改并留 B → 按图认出 A → 取到新目录 → 让 Agent 使用副本继续改。**

环境由 Agent 检查、复用或按已获授权的官方方法安装。熟悉环境的用户使用命令参考；普通用户不需自行拼环境变量，不增加内置 AI Key 或模型设置。

降低主动保存成本：首次只问一次是否截图，答案按项目保存，失败或待配置时仍保留；用户可一次明确委托本轮修改前后留稿；沿用已知项目和截图偏好，不逐次重问。工作台名称可选；确认偏好后可直接或用快捷键留稿。整稿取回提供包含准确新目录与版本的继续修改指令。它们减少重复步骤，不构成后台监控、每次编辑自动保存或跨客户端自动触发的承诺。

首页和首次使用只解释安装、留稿、凭图取回。Git、旧目录归并、去重、备份迁移、存储、版本删除、环境管理和兼容接口保留为按需入口。全部功能与维护边界见 [FEATURES.md](FEATURES.md)。现有文件、旧包、数据和失败诊断继续保留。

**通用功能扩展冻结。** 本阶段只优化主流程真实卡点、错误反馈及必要的完整性与兼容性。没有新的具体任务依据，不启动云同步、通用清理、后台自动快照、新 AI 界面或其他扩展。

维护者的本机任务与自动检查可支持预览交付；新机器安装、其他客户端原生接入和外部用户自然复用仍需分别验证。下一步沿用 [5–8 人定性试用任务](PRIVATE-TEST-TASKS-20261024.md)，不把演示、Star 或测试数量当实际采用。

# Reprise 当前产品简报

2026-10-24 · 现行方向。当前源码 Skill 与可选便携包为未公开的 0.8.0 候选，不能把本文当作全部能力已验收或正式发行说明。

服务正在用 AI agent 或编辑器反复修改本地网页、希望凭画面认出旧稿并取回的人。主线是：**修改前保存 A → 改成 B 再保存 → 在工作台凭图找到 A → 取出到新文件夹继续改。** 不要求用户读 SHA 或操作 Git，版本与恢复正确性由产品及观察者核验。

主要交付为轻量源码 Skill 和脚本，包含固定本地核心与可视工作台；agent 先复用环境，缺少依赖时按官方方法和正常授权安装，开发者使用已有基础环境。本次只交付源码 Skill 和双语内容包。首次接入后选择 Reprise Skill，说“打开”；只打开不导入或保存当前目录。只有保存请求才产生新稿，文件与画面分别报告结果。中文“倒带”和英文 Reprise 是同一名称，通用 `@` 别名尚未证实。App 壳不是主产品，也不增加内置 AI 或模型设置。

首页只解释用途、一个场景和一个示例；接入细节放[快速开始](QUICKSTART.md)与[Skill 说明](AGENT-SKILL.md)。Git、迁移、备份、旧目录整理、版本删除和环境管理保留为按需能力，不作为当前新用户任务或主要传播内容。详细范围见[产品方向](PRODUCT-DIRECTION.md)。

下一步建议只做 5–8 名匹配人群的定性试用，使用他们正在修改且愿意用于试验的网页，记录帮助次数、识别是否正确、取回后是否继续修改，以及有真实机会时是否再次使用。人数和停止条件是人为决策线，不是统计证明；维护者自测、合成样本、观看、收藏与 Star 不计作独立完成或复用。目前没有足够的外部成功证据。具体方案见[试用任务](PRIVATE-TEST-TASKS-20261024.md)与[分享简报](SHARING-BRIEF.md)。

# Reprise 下一阶段产品指令

把 Reprise 做成让有真实重复任务的人能够独立使用、愿意再次使用的本地版本工作台。先聚焦“主动保存本地项目/创作资料的版本，看懂两版变化，准确取回需要的旧文件”，保留现有 Git 只读历史和旧归档兼容。GitHub 有效互动和 Star 是传播结果，不能替代任务完成和复用。

当前明确主流程是：保存版本 → 用精确截图、文件或实际运行认准版本 → 选择一个或多个旧版本 → 解释丢失的完整历史状态、仍共享内容和联合回收口径 → 明确删除 → 核验所有保留版本并报告实际变化。另将可重建依赖与原始资料分开：源码和输入保留，实际验证过的受管环境可以释放，需要时重新构建；不能将个人文件删除当作远端取回。优先本地操作，不依赖模型生成删除判断。

当前评估阶段只在合成样本中查看、比较和预检，不执行新的版本删除或环境释放，不接入真实资料，不公开发布。完整执行路径保留在产品里；此前隔离测试的执行回执只作为已有证据。体验文档以不清除内容的路径为默认，不自动运行删除演示或破坏性回归。这个阶段约束不改变未来用户对具体版本作出明确删除授权后的产品能力。

0.7.0 本地候选已经把查看、预览/运行、联合删除预检、明确执行、保留版本校验以及受管环境重建串起来。当前最值得验证的产品承诺是：**用户能够认准要保留的一版，并在作决定前理解放弃其他版本的代价。** 精确版本证据、共享内容解释和恢复校验共同支撑这个承诺；“功能已实现”不等于用户已能独立使用，也不证明竞品没有这些能力。

先核对当前源码、已安装 Skill、公开发行、此前决策和实际测试，分别标明已实现、仅本地、未实现、未验证。并行研究目标用户近期任务、成熟替代品、真实失败与官方 GitHub/搜索指南；保留日期、原始来源和证据限制，不编搜索量、需求规模、增长原因或成功案例。当前假设有反证时要收窄或放弃。

每轮选择一个能明显降低任务成本的改进。优先修数据完整性、恢复正确性、首次上手与流程中已观察到的阻塞；不为功能数量加入系统清理、云盘、完整 Git 写操作、语义合并或新的常驻服务。普通文件夹与 Git 保留准确来源，共用操作界面即可，不强行统一不同的存储语义。

交付包含一个自建且可供公开的无私密样本、一条可以复现的完整流程、准确能力与隐私边界、失败诊断、适当回归及独立审阅。实际发布仍须遵守当轮授权。空间结论分开报告逻辑字节、存储新增成本、分配块和实际卷空闲变化；版本检查、实际恢复、独立介质备份与程序可运行分别验证。不得把选择清单说成已经删除，不得把本地恢复说成远端下载。

Skill 作为自然语言入口，应根据用户目标调用最短路径，不让用户学习内部 ID 或反复提供已有信息。先保留当前稿，再将选定旧文件恢复到新目录。只问占用不主动保存全部文件；只要求预检不展开完整副本。已有版本、名称和数据目录继续复用，歧义才询问。核心不能完成的操作要说明，不用临时脚本偷偷扩大其能力承诺。

保持原始文件、版本数据、既有改动、旧运行时及所有失败产物。本地实现与可审阅材料可以继续完成；外部发布、联系他人和真实文件移除遵守已有明确授权。当前保持本地，不公开发布。候选发布前让实际下载包、版本说明、README 和演示一致，不把本地功能冒充公开可用。

需求验证建议：两轮合计 10 位近期确有同类任务的用户，目标至少 8 位独立完成主流程；后续 14 天确有使用机会的人中至少 3 位主动复用并能说明选择理由。这些是项目决策阈值，不是行业标准。记录原方法、首次及再次总成本、帮助次数、正确恢复、真实反馈；用自愿提供的匿名资料，不引入默认遥测。没有招募到有效样本就是验证未完成。

在当前不执行清除的体验中，优先观察三件事：用户能否依靠标题、截图、文件或预览选对指定旧稿；能否解释“独占内容为零仍会失去一个历史状态”以及“联合收益不能逐项相加”；能否分清“文件可恢复”“曾成功运行”和“未来能否重新下载依赖”。记录完成时间、求助与误判，先修观察到的问题。恢复、删除和重建的执行正确性使用既有测试证据单独报告，不能由口头理解或预检通过代替。推广材料先围绕这条具体任务制作，待重复使用证据出现再扩大范围。

推广先展示三类真实内容：普通文件夹两稿恢复、网页历史的精确比较与取回、去重与实际磁盘收益的区别。再用准确 topics、英文入口、贡献与反馈渠道帮助合适的人发现它。SEO/GEO 以可抓取、可引用、有版本和证据的内容为基础，不承诺排名、模型引用或爆火。

每轮明确报告：做了什么、证据是什么、哪部分仍未解决、当前是否值得继续。两轮后仍没有实际替代价值或主动复用时，明确建议缩为个人工具或停止泛化产品投入，不继续用“再补几个功能就完美”延长开发。
