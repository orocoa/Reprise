# CI 制品保留策略

正式可用版本与回退文件以 GitHub Releases 为准：保留发布包、源码包、ARTIFACTS.json 和 SHA256SUMS.txt。CI 制品是有时限的验证证据，不是用户快照或唯一恢复来源。本次策略不删除现有 Release、保留制品、运行记录或本地资料。

- 成功任务保存必要日志、安装校验报告和输入溯源，7 天后过期；每个任务最多 10 MiB。
- 失败任务额外保存有体积限制的截图和视频，14 天后过期；每个任务最多 20 MiB。
- 仅成功的 main 推送在 Linux/Python 3.9 的一个任务中附带两个便携 Skill 包，避免三个平台重复上传同一用途的包。它们是 CI 候选，不能替代已验证的正式 Release。
- 不上传临时 venv、依赖缓存、node_modules、冻结源码副本、测试快照、嵌套诊断归档或整个 work/test-artifacts。
- 单份日志最多保留末尾 1 MiB；单份报告最多 2 MiB；失败画面最多 4 MiB。清单记录原始大小、实际大小、截断标记、SHA-256 和省略原因；原始本地文件不修改、不删除。
- 制品上传失败只产生警告，真实测试、安装验证与打包失败仍使任务失败。运行摘要和日志独立保留。

这项策略适用于新的 CI 制品，已保留的最新主分支、v0.8.7 与 v0.8.6 制品不在本轮删除范围。GitHub 的已有账期累计用量不会因更改保留期而清零。

验证：`python3 -m unittest discover -s tests -p test_ci_artifacts.py -v`；完整跨平台回归仍由原有 Reprise checks 矩阵执行。
