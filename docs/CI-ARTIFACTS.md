# CI 制品保留与替代清理

正式可用版本及回退文件保存在 GitHub Releases：发布包、源码包、ARTIFACTS.json、SHA256SUMS.txt 不受本清理流程影响。用户快照、截图、运行环境和本地诊断不在清理范围。

## 保存内容

按用途收集必要日志、安装验证报告和输入溯源；失败任务增加截图和视频。不设任务总量、单文件大小、文件数上限，也不截断日志。临时 venv、源码副本、依赖缓存、测试快照和嵌套归档仍不上传。成功的 main/Linux/Python 3.9 任务附带两个便携候选包，避免平台重复。

不再设置 7/14 天自定义到期。公开仓库 Actions 制品仍受 GitHub 平台的最长保留期约束（当前仓库为 90 天）；需要长期保存的正式版本和恢复包继续使用 Release。

## 何时删除

成功的 Reprise checks 完成后，单独的清理工作流从默认分支执行经过审核的脚本：

- 先确认当前 main 的三个平台完整通过，且三份非过期制品都存在；否则全部保留。
- 保留最新可用 main、当前合并来源的验证制品（可作为待发布来源），以及最近两个正式稳定版的恢复/验证制品。
- 仅删除被这些完整制品替代的旧 main 构建、已合并且已由当前 main 验证覆盖的 PR 制品，以及同一运行内被完整重试替代的旧尝试。
- 开放 PR、未合并的失败、用途不明和缺失替代品的制品先保留。删除不按年龄或体积判断。
- 每次删除前重新核对 main、正式版本和精确制品 ID；发生变化就停止。只删除 Actions 制品，不删除 Release、源码、工作流运行或日志。

有写权限的清理任务只读取可信默认分支代码，不执行 PR 代码、不下载或运行制品。日志和运行摘要记录清理计划与实际结果，不再为清理报告创建制品。手动运行默认只列计划，显式启用 apply 才删除。

上传配额错误仍只产生警告；真实测试、安装和打包失败仍使原任务失败。此策略不改变 GitHub 已累计的账期用量。
