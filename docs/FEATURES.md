# Reprise 功能范围与入口

2026-10-31 · Reprise 0.8.5 当前功能与维护范围。

产品定位：**为正在用 Agent 或编辑器反复修改本地网页的人，在关键修改前留稿，以后凭画面认稿，取出新副本继续改。**

## 默认只走这条流程

1. 将完整 Skill 包交给 Agent 安装。Agent 检查、复用或按授权补齐环境，然后打开工作台。
2. 首次按项目询问一次是否保存画面，先记住答案；之后在项目已明确的对话里说“本轮修改前后都帮我留稿”。Agent 在修改前和本轮结束后各保存一次，分别报告文件和画面结果。
3. 在工作台按图选稿，按需比较，取出新副本。复制继续修改指令给正在做网页的 Agent，让它使用取回目录。

网页画面需要对应版本实际采集。未保存的内容无法事后找回；截图不是外部服务、依赖或数据库的完整备份。

## 已有功能如何安排

| 层级 | 已有能力 | 入口与范围 |
| --- | --- | --- |
| 主流程 | 安装、打开、正常停止 | Skill；[接入说明](AGENT-SKILL.md)。打开不会导入或保存当前目录。 |
| 主流程 | 保存、名称与时间、视觉历史、收藏与搜索 | 工作台。名称可选；未变化时沿用已有稿件及名称。 |
| 主流程 | 画面与文件比较、整稿或指定文件取回、读回校验 | 选定版本。画面绑定准确版本；取回使用新目录。 |
| 减少重复操作 | 记住截图偏好、按时间命名、快捷键留稿、继续修改指令 | 首次是/否选择持久化后持续复用；失败或待配置不重置答案。 |
| 按需配置 | 静态网页截图；受支持 npm/Vite 的安装/运行计划；手工截图 | 版本画面与保存设置。命令先审阅保存，再在独立副本执行；其他框架沿用明确运行配置。 |
| 主流程 · Git 项目 | 原 Git 历史与图谱、关联存档、详细差异 | 原始 Git 保持只读；普通目录快照的保存顺序不冒充源 Git 历史。 |
| 高级管理 | 旧目录/ZIP 内容归并、成本预检、重复内容与原件候选报告 | 设置 → 高级管理；[旧副本导入](FOLDER-IMPORTS.md)。报告不自动移除原件。 |
| 高级管理 | 独立备份、新库恢复、迁移与重新关联 | 设置 → 高级管理 → 备份与迁移；[备份说明](BACKUP-AND-MIGRATION.md)。 |
| 高级管理 | 完整性、存储占用、显式历史版本删除、运行环境检查与释放 | 设置 → 高级管理；[版本生命周期](VERSION-LIFECYCLE.md)。删除与释放沿用明确确认和原有校验边界。 |
| 保留兼容 | 旧归档、历史 CLI/包格式、可选 AI 接口、原生壳原型 | 开发者参考与现有适配器；不放入首次使用主线，不扩大其已验证范围。 |

全部已有文件、旧包、数据、接口和诊断保留。界面收口只改变入口层级，不删除既有能力。

## 通用功能扩展冻结

本阶段只处理主流程中观察到的安装、保存、出图、认稿、恢复、继续修改和故障反馈问题，以及必要的数据完整性、兼容性修复。

暂不启动云同步、团队协作、通用文件清理、后台自动快照、Git 写入客户端、语义合并、新 AI 对话/模型设置或新的框架适配计划。未来扩展需要新的具体任务依据，不作为“更完整”的默认待办。

验收看实际任务：能否顺利接入、正确留稿、凭图取回、找到副本继续修改；有下一次机会时是否主动再用。测试通过、观看或 Star 不替代外部真实使用证据。
