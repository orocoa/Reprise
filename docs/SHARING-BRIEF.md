# 倒带 / Reprise：小范围试用与分享简报

2026-10-24 · 经多角色审阅修订，未发布、未邀请用户。当前内容面向 **0.8 本地候选**；GitHub 旧公开版 v0.4.1 不是这份演示的下载入口。旧稿保留于维护者本机评审档案，不作为本文的使用前提。

## 一句话、一个场景

**修改前留一稿，以后凭画面找回来。**

你正和 AI agent 一起改本地网页：间距收紧了，颜色换过了，后来又想用之前的样子。倒带 / Reprise 让你在想保留的时候存一稿，再到可视工作台按画面认出它，取回一份副本，继续修改。它需要提前保存；文件已保存与画面是否保存成功，会分别告诉你。

English equivalent: **Save a draft before your next change, then find it later by how it looked.** Save a draft with Reprise while working with your AI agent, then use the visual workbench to recognize it and retrieve a copy. You need to save it first; saving files and capturing their appearance are reported separately.

主要交付是包含脚本和固定核心源码的轻量 Skill，配合可视工作台；agent 先复用环境，缺少依赖时按官方方法和正常授权补齐。展示时只讲这一个任务：先保存，再认稿、取回。Git、运行配置、备份迁移和存储管理保留在按需展开的说明中。

可直接编辑的中英文小红书 / GitHub 分享稿见[分享成稿](SHARING-COPY.md)；[English brief](SHARING-BRIEF.en.md)。

## 可供试用邀请使用的短介绍

> 你最近有没有把本地网页改了几版，又想找回之前的样子？我做了倒带 / Reprise：在和 AI 改网页时保存一稿，之后按画面认出来，取回副本。现在想观察几位确实有这个任务的人试一次，看看能否找到对的稿、哪里会卡住。它还在本地候选阶段，先确认你的电脑、客户端和网页能完成这条流程，再提供对应包。

这段话用于将来获准邀请时，不是已发送的消息。先确认对方近期有具体任务和原来的处理方法，不用“帮我支持一下”代替试用目的；无需要求 Star 或好评。

## 约 42 秒的真实演示脚本

使用可公开的合成静态 HTML 项目，画面中标明“0.8 本地候选演示”。录制前核对包、说明和示例是否一致。以下是分镜计划，尚未录制。

| 时间 | 实际操作与画面 | 旁白 / 字幕 |
| --- | --- | --- |
| 0–5 秒 | 编辑器与当前网页 A 并排，准备尝试收紧间距。 | “这一版先留着，再让 AI 改一轮。” |
| 5–13 秒 | 用客户端真实支持的入口选中 Reprise Skill，说“保存这一稿，叫‘收紧间距之前’，同时记住画面”。显示 A 的文件保存与画面采集真实结果。 | “修改前，先告诉倒带保存这一稿。” |
| 13–22 秒 | 实际改出可辨认的网页 B，再说“保存这一稿，叫‘收紧间距之后’，同时记住画面”。显示 B 的文件保存与画面采集真实结果。 | “改出另一版，再留一稿。” |
| 22–27 秒 | 在同一客户端选中 Skill，说“打开”。只展示工作台，不产生新的保存。 | “还是想试之前的样子，就打开倒带。” |
| 27–33 秒 | 在两稿画廊按截图选回 A，让观众看清画面差别。 | “按画面，认出想找的这一稿。” |
| 33–42 秒 | 取回 A 到新目录，显示结果位置；在取回稿上实际做一处小改动，并排保留当前 B。 | “取回副本，接着改。现在这稿也还在。” |

演示要求：

- “打开”和“保存”是两个意图；只说打开时不得顺手保存当前目录。录制前必须确认这个行为，不能用字幕掩盖误存。
- 不把目标中的 `@倒带` / `@Reprise` 写成各客户端已实现的别名。画面只使用该客户端已核对的真实选择方式；具体语法见[Skill 接入说明](AGENT-SKILL.md)，首页和旁白不堆客户端差异。
- 操作、截图和恢复文件来自同一确切版本。画面缺失就显示缺失，不借其他稿的截图，不用模拟动画伪装操作证据。
- 可剪去等待，但保留完整记录并注明剪辑；42 秒是视频长度，不是安装或任务耗时承诺。恢复后的静态样本要实际核对，不能只展示成功提示。
- 不露私人路径、账户、密钥、真实客户资料。只使用合成项目或获得明确展示许可的内容。

## 一次小样本试用怎么观察

找 **5–8 位正在用 AI agent 或编辑器做本地网页、近期确实想找旧稿的人**，进行定性排错。先记录最近一次任务和原方法；每个人在自己的可试用网页副本上保存两稿，随后只凭画面找到指定旧稿，取回后继续改一次。非开发者无需阅读 SHA、Git 或存储报告，版本对应与当前稿是否安全由观察者核验。完整任务单见[私下任务验证材料](PRIVATE-TEST-TASKS-20261024.md)。

开始前先问“最近哪次想找旧稿、原来怎么找、这次想取回什么”，不要先教对方为什么需要 Reprise。安装、首次打开和任务操作分开计时；记录口头提示、代操作、失败和放弃。维护者自测、合成演示或按教程照做，不计为外部用户独立完成真实任务。

| 观察环节 | 记录什么 | 怎样判断 |
| --- | --- | --- |
| 看懂用途 | 对方会拿它做什么 | 能说出自己的本地网页、主动留稿、凭画面取回；若以为会自动记录每次修改，记为理解失败 |
| 接入与打开 | 设备、客户端、候选包、首次阻塞；只请求打开的结果 | 工作台打开，未意外保存或导入当前目录；安装问题单列 |
| 保存两稿 | 项目是否明确、两次保存与截图结果、需要多少帮助 | 两稿来自同一正确项目且画面可辨；只有文件保存不算本轮视觉任务完成 |
| 凭图辨认 | 用户先选目标画面，再在画廊找到对应稿 | 不提供版本名、时间或序号答案，不由开发者指出；参与者无需读版本标识 |
| 取回继续改 | 结果位置是否找得到，能否从取回稿继续做一次改动 | 观察者核对内容属于目标稿、当前项目仍在；成功提示不能代替核验 |
| 后续机会 | 14 天内是否再次发生类似任务、如何处理 | 有机会时是否主动再用，以及比原方法具体省了哪一步；没有机会、失访分别记录 |

每人保留匿名任务记录，不默认采集项目内容或加入后台遥测。报告实际人数与帮助情况，例如“6 人尝试，3 人独立完成，2 人需要提示，1 人未完成”；不要只报成功率。5–8 人是人为选择的定性排错规模，不能推出市场比例。本轮只按上述任务单执行；旧传播计划已标为历史，不再并行运行另一套人数与渠道要求。

## 什么时候停，什么时候继续

- **立即暂停试用和传播：** 误存无关目录、覆盖当前项目、取回错稿、损坏报成功，或候选包与演示不一致。保留证据，修复后重测受影响流程。
- **暂停扩大邀请：** 安装、打开或框架运行反复阻塞；先修这条路径。静态 HTML 的成功只支持相同条件，不能抵销 Vite/React 等真实任务的失败。
- **值得继续小范围试用：** 有人能独立完成，说明画面认稿或取回比原方法具体省了哪一步，并在再次遇到同类任务时主动使用。优先服务这类任务；一个人的成功仍不足以推及所有用户。
- **收回个人工具：** 集中修正入门阻塞后，有再次使用机会的人仍没有复用，或普遍认为原有编辑器历史 / Git / 手动副本更省事。保留源码、个人流程和已有资料，停止为扩大受众添加通用功能；没有招到人则是验证未完成。

GitHub Star、收藏、观看和评论说明传播兴趣。下载或 clone 说明尝试入口被使用。正确完成和有机会时主动复用才说明实际使用；各自有价值，互不代替。Star 上涨不能抵销恢复错误，也不能把无人试用改写成需求成立。

## MIT 开源是否值得

**值得保留 MIT 开源，并在交付条件明确后做有限试用；现在没有依据把它称为已验证的独立产品。** 仓库的 [LICENSE](../LICENSE) 是 MIT，依赖与随包组件的许可另见[第三方说明](../THIRD-PARTY-NOTICES.md)。公开源码可以让人检查工作方式、复现问题和提出具体改进；许可证本身不会带来需求或替用户完成首次任务。

作者提出了“凭画面认稿并取回”的具体任务，自用体验可作为开发动机，不作为外部需求证据。截至 2026-10-24，[Cursor 官方说明](https://cursor.com/docs/agent/overview#checkpoints)提供会话中的文件检查点，[design-history 项目说明](https://github.com/kingermayank/design-history)提供网页截图历史、非提交时刻采集和 agent 接口；本次只核对文档，未实测竞品。它们支持“值得找几位匹配用户试一次”，不证明别人愿意更换现有方法。相邻工具的热度、旧 issue、作者自测都不是 Reprise 的采用证据，也不支持“独有、唯一或首创”的说法。

剩余假设很具体：**把画面认稿、准确文件和取出新副本连成更少步骤，收益能否超过安装和主动保存的成本。** 观察前先让对方展示原方法；没有旧历史时不编造困难的前测。对只需撤销刚才一次修改、或 Git 加截图已经够用的人，没有必要强行推荐额外工具。

尚未验证的是：外部用户是否愿意接入 Skill 并准备缺少的依赖，是否记得主动保存，截图能否帮助辨认其真实网页，以及有下一次机会时会不会再用。轻量源码包不捆绑运行工具，不等于没有依赖；现有环境不足时仍有安装、下载与授权成本。

只有自用价值也可以保留一个清楚、可复现的开源工具。是否继续扩展，取决于是否出现同类用户的具体收益，以及维护是否值得；不需要企业化或收费来证明它有用，也不应靠不断增加功能证明过去的投入合理。

## 当前可讲的事实与待核对项

主交付改为轻量源码 Skill + 脚本。它复用或在正常授权下准备宿主依赖，不捆绑另一套 Python/Node/Git/浏览器；使用 Skill 不要求用户申请 Apple Developer 证书。

本机原样源码 Skill 已用现成的 Codex Python/Git/Node/Playwright 和已有 Chrome 完成 doctor、两稿及真实图片、CLI 恢复字节核对、中英文打开与正常停止。没有新装依赖、下载工具或修改全局配置。这个证明只覆盖该机器的现有环境和 CLI/合成夹具，不证明缺依赖的新 Mac 自动安装、跨 agent 截图、原生导入或外部用户独立成功。doctor 仅检查基础工具/包完整性，实际截图另行验证。

完整运行测试包已因下载首开验证阻断撤回；历史诊断继续保留，不作为当前安装路线。

此前核心全量回归保留一次原因未明的任务等待超时；原样单项和所属模块复验通过，不等于全量全部通过。新 Skill 说明/打包入口的针对性检查与源码 ZIP 身份，按其对应验收回执记录，不冒用旧候选总数。接入与依赖见[Skill 说明](AGENT-SKILL.md)；WorkBuddy / TRAE 原生操作仍延期，真实采用和持续复用仍未验证。

建议下一步只做：固定一个与文档一致的候选、完成受支持环境的交付验证，再按唯一任务单观察 5–8 位匹配用户。这轮不扩平台或通用功能；广泛推广仍缺实际使用证据。暂不做广泛下载推广，不以旧 release 承接新演示，也不扩充宣传素材数量。本文件不授权发布、邀请、私信或第三方评论。
