# Reprise one-page trial task

October 24, 2026. Unpublished 0.8 candidate. This is the English version of the [single trial plan](PRIVATE-TEST-TASKS-20261024.md), not a second recruitment or measurement scheme. No participants have been recruited and no results are implied.

Observe **5–8 people who are currently editing local websites with an AI agent or editor and recently needed an earlier draft**. The sample is a qualitative effort limit, not statistical proof. Do not expand platforms, general-purpose features or promotion channels in this round.

## For the participant

Use a local webpage you are working on. Save the current draft and its picture. Make a change you already wanted to try, then save the second draft and its picture. Choose the earlier appearance you want to revisit. Later, use that image to find the draft in Reprise, retrieve a copy and edit it again. Keep your current project too.

Use a nonsensitive project copy with the participant's consent, keeping the original. Explain candidate and environment limits first. Without a real task, label the exercise as practice. “Open” must not save or import the current directory. Use the client's actual Skill selection method; do not assume a universal @ alias.

## For the observer

| Stage | Record |
| --- | --- |
| Existing method | Ask about a recent retrieval task. Observe the existing method when usable history exists; do not invent a difficult baseline. Without a matching task, record a mismatch. |
| Setup | Package version, device, client, setup/opening time and blockers. Keep setup separate from task time. |
| Two saves | Correct project, saved files and a corresponding picture for each draft. A missing image stays missing. |
| Visual recognition | The participant chooses the target picture. Later show only that picture as the task prompt, without revealing its title, date, number or card. Normal interface labels remain visible. |
| Recover and continue | The participant finds the recovered copy and edits it. The observer verifies that its files match the pictured version and that the current project is unchanged. No Git or SHA knowledge is required of the participant. |
| Later opportunities | For 14 days, send no saving reminders. Record real opportunities, voluntary reuse and naturally occurring retrieval. The initial two-draft task only checks operation; no opportunity and loss to follow-up remain separate unknowns. |

Give everyone the same normal instructions. Do not point to buttons or operate for them. Record any hints, intervention or fixes and mark those attempts as assisted. Maintainer tests, synthetic demos and guided walkthroughs do not count as independent completion of a real task. Saving files without a picture does not complete this visual task.

Keep one anonymous row per participant: task and existing method; environment and package version; setup blockers; both file/picture results; correct recognition; recovery and continued editing; observer correctness checks; independent or assisted; time and obstacles; later opportunities and reuse; concrete benefit or reason not to use it. Do not collect private paths, files, credentials or unredacted logs. Report actual counts, assistance and unknowns rather than only a success percentage.

## Decide whether to continue

- Wrong project saved, current project overwritten, wrong version recovered, corruption or wrong image reported as success: pause the affected path immediately, preserve evidence and retest after repair.
- Repeated setup or framework blockers: pause expanding invitations and fix that path. A static sample passing does not offset real-project failure.
- Independent completion with a concrete reduction in effort is a reason to keep observing. Unprompted reuse when the same need returns is stronger evidence.
- After the observation period, make at most one focused correction for observed blockers. If people with another real opportunity still do not reuse it or find their old method easier, keep the personal tool and stop general-purpose expansion. Missing participants, missing opportunities or loss to follow-up are not successes.

The hypothesis is fewer steps from a recognizable picture to correct files and an editable recovered copy. It is not technical uniqueness. Stars, bookmarks and views measure interest, not correctness or reuse. Old cleanup, version-deletion and storage exercises are excluded from this trial; they remain engineering checks where relevant.
