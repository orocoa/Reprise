# 本地交付与安全边界

## 推荐交付模式

首版保留「本地服务 + 系统浏览器」界面。使用者需要一个明确的启动入口、依赖检查、打开页面和停止服务的方式；不需要为了安装方便重写原生 UI。

当前构建产物是 Python wheel 和源码包。wheel 包含 Reprise 与网页资源，不包含 Python、Git、Node 或浏览器。开发者可使用独立 venv；用户级安装也必须正确定位包内资源。`scripts/check_distribution.py` 从源码目录外验证直接 wheel 与源码包重建 wheel 在全新 venv、独立 user-site 中的实际 HTTP 结果及资源哈希。

面向没有开发环境的用户，下一步建议按操作系统和 CPU 架构提供运行环境包：

- 必需组件：受支持的 Python、Git、Reprise、网页资源、启动/停止入口与版本清单。
- 可选采集组件：Node、固定匹配版本的 Playwright 与 Chromium。缺少它们时，仍能浏览 Git 历史、比较文件和导入人工证据。
- 用户项目、密钥、运行副本和证据始终存放在应用数据目录，独立于可替换的软件目录；升级不覆盖这些数据。
- 启动器检查端口和依赖，打开 loopback 页面；应提供可见的运行状态、停止入口和可导出的本地诊断。

不能把开发机现有 `.venv` 直接压缩当成通用环境包。Python 官方文档明确说明虚拟环境通常不可搬移；其中的解释器路径与脚本路径依赖创建位置。应在目标机创建环境，或另行制作并验证可分发的运行时包。

依据：[Python venv 文档](https://docs.python.org/3/library/venv.html#how-venvs-work)。本次修改不声称已经交付完整运行时包、原生 App、安装器签名或自动更新系统。

## 从 PersonalWeb 安全讨论迁移的原则

参考了用户指定的 [PersonalWeb · 网站防护与用量提醒 · 2026-10-01…](thread://01a0f7f2-2514-75a3-ad75-72c758b124ff?hostId=local) 及该任务记录的本地交付证据。其场景是公开网站的原件保护、访问控制、限流及费用提醒；Reprise 当前是本机工具，因此采用相同的验证原则，并按本机访问与进程权限落实措施。

| 原讨论的经验 | Reprise 的落实方式 |
| --- | --- |
| 不能只检查一个域名或一个成功页面 | 管理 API、静态预览、安装后的资源入口分别验证；Host 必须精确匹配本机地址与端口，重复 Host 也拒绝。 |
| 只从发布文件中移除资源，不代表所有入口都不可访问 | 软件包只包含应用资源；应用数据目录不作为网站根目录。证据接口仅暴露登记的媒体，不提供任意本地文件下载。 |
| 防护应覆盖真实执行边界 | Git 读取不执行外部过滤器；静态服务器以可信绝对脚本和隔离 Python 启动，不把仓库当作模块来源。 |
| 正常访问应保持顺畅 | 本机浏览不新增账号、验证码或每次点击授权；会执行项目代码的命令配方仍需明确保存和批准。 |
| 提醒不是硬限额，结果必须与实际状态一致 | 停止过程必须确认自有进程树清理结果，无法确认时报错；保留超时、失败和取消诊断，不把失败标成成功。 |

本轮没有修改 PersonalWeb 的网站、Cloudflare 配置或提醒，也没有新增定时监控、邮件或外部 AI 调用。

## 持续保持的边界

- 服务仅绑定 loopback；管理 API 保留 Host、Origin、写请求 token 与请求体限制。静态预览与管理 API 使用不同来源。
- 静态服务使用 `python -I -S <trusted static_server.py>`，从托管目录启动；仓库中的同名包、标准库同名文件与 Python 启动钩子不参与加载。`-I` 与 `-S` 的职责见 [Python 启动选项](https://docs.python.org/3.9/using/cmdline.html)。
- 命令型项目仍以本机用户权限执行。独立副本及进程跟踪不等同于容器/虚拟机隔离；运行任意恶意命令需要独立的隔离适配器，不能由本次修复推导出安全保证。
- 进程所有权按启动身份与持久记录校验，不能按名称或端口杀进程；身份无法确认、记录损坏或清理失败应明确报告。
- AI 默认关闭、调用由用户动作触发，提案不自动执行。服务商费用提醒、消费上限和本地次数统计是不同功能；当前不承诺服务商费用硬封顶。
- 证据绑定准确提交和采集输入，快照、失败日志和原始媒体保留。空间用量展示、备份/恢复和未来更新包校验应在面向非开发者的环境包中验收。

## 发布验收

现有完整测试之外，必须覆盖：未批准的同名 Python 包和启动钩子、clean/process filters、父进程退出而子进程继续运行、身份错配不误杀、静态预览错误 Host，以及从源码目录外启动的全新安装。

macOS 和 Linux 的支持范围应分别有实际验证记录；不能用一台开发机的成功结果替代跨平台发布验证。

## 2026-10-09 功能修复范围

本轮按用户要求保持命令行工具模式，没有制作 App、运行环境包或新发行包。`reprise .` / `--no-browser` / `shutdown` 已提供可验证的启动、复用及停止入口。原先快速双重派生并切换会话的残留子进程，通过启动前继承标记与停止前两次独立扫描补齐；清理仍校验身份，并保留无法确认的错误状态。主动移除标记的恶意代码不属于容器隔离保障。

网页资源继续由包内资源定位方式提供；新的 locale/shell/样式文件覆盖既有包数据通配规则。之前全新安装矩阵的原始证据保留，本轮不以旧包证明新包已经发布。后续正式发行时应对最终版本再次执行安装矩阵。
