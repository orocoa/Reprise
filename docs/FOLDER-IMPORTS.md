# 多目录、发布包归并与恢复核验

Reprise 0.8.0 保留的按需归并功能，不会删除原件或发布网站。工作台「项目」→「把多个旧文件夹或 ZIP 整理成版本」创建合集；已有文件夹项目可在设置中明确追加旧目录。最后一个输入是保留的当前目录。

归并保存按文件内容共享存储，每版保留独立清单、来源与 SHA。顺序由用户确认；导入顺序及保存时间不代表原始开发史。程序逐版恢复到新目录并读回，之后才给出原件候选。原件改变、Git 未覆盖、硬链接、进程使用情况不明、库或恢复副本损坏都会阻止候选结论。

```sh
python3 run.py --data /new/reprise-data import-folders --manifest /inputs/versions.json --check
python3 run.py --data /new/reprise-data import-folders --manifest /inputs/versions.json --preflight FINGERPRINT
python3 run.py --data /new/reprise-data import-folders --manifest /inputs/versions.json
python3 run.py --data /new/reprise-data folder-import-report REPORT_ID --refresh
```

导入先预检成本，再保存与验证。`--check` 只读目录元数据与 ZIP 目录，不读取正文、不保存版本、不生成恢复副本；新增内容共享量尚未知，展示 0 到全部展开量的逻辑范围、完整恢复副本展开量及含元数据预留的容量预算。预算不是物理分配保证或预计释放量，跨卷不合并算净收益。空间不足、输入变化或排队期间变化会阻止保存，不能先删原件腾空间。`FINGERPRINT` 使用预检返回的指纹；显式直接导入仍有容量检查。

正文扫描完成后再次绑定预检身份；每版发布前核对已扫描的精确来源状态与剩余容量预算。扫描中或发布前改变的输入不能成为新的默认基线。输入目录内及受管目录中的嵌套跨设备挂载不受支持，须按磁盘分开管理；不能把挂载子树的分配量算到根目录所在卷。

重复完整审阅优先复用同一项目、精确 SHA 和完整范围的内部恢复副本，并重新读回；损坏、被修改、缺失或范围不符则失效，旧副本和诊断保留。已有报告刷新不重新展开。首次逐版实际恢复仍会新增完整副本，本版不自动清理，因此初次归并的模型净收益仍可能为负。

读回会核对每个文件打开前、读取后和路径的身份，并在全扫描结束时重新核对清单及根目录状态；扫描期间变动使验证失效。这个结果是本次核验，不把可编辑的恢复目录变成永久不可变副本。

清单包含 `name` 与按旧到新排列的 `versions`；每项包含 `path`、`title`。追加既有文件夹项目须提供 `project_id`。最后一项须为当前工作目录。所有原件保留。

ZIP 项只有明确填写 `zip_mode: contents` 才会拆解最外层并按内部文件去重。不保存展开中转副本，但仍保留实际恢复校验副本。这个模式不能恢复原始 ZIP 的每个字节、封装元数据或签名；需要原始发布包身份时保留原包。嵌套压缩包不会递归拆解。ZIP 未提供本机扩展属性，不把未知伪装为空；普通文件夹仍严格验证已保存的扩展属性。

报告分别展示候选原件大小、分配块模型、新增版本库/记录/校验副本，以及扣除成本后的模型净收益。保留全部校验副本时可能净增加占用。另行移除校验副本的条件模型不代表已有授权或可自动执行。实际卷释放量未知，本轮实际释放为零；报告有时间范围，行动前须重新核对。恢复到新库后旧候选结论失效。

以后保存网站发布历史，可以持续使用同一个当前输出目录，每次 `save /site/dist` 保存一版；相同资源不必重复进入历史库。支持目录上传时无需为了留历史再造整站 ZIP；平台要求 ZIP 时仍需生成。Reprise 不替代网站构建、部署或托管平台的存储规则。原件与历史库是两份占用，完整恢复/导出同样会增加空间。

输入、元数据与体积限制见 [Skill 归并范围](../skills/reprise/references/folder-imports.md)。尚未验证真实大型项目或 150 GB 工作集；不能把合成示例的去重率当作真实回收承诺。
